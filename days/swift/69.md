# Day 69: Animations - Phase & Keyframe Animation

## 📝 Today's Tasks

1.  **Use `PhaseAnimator`:** Cycle a view through discrete phases automatically.
2.  **Build a Keyframe Animation:** Drive multiple properties over a timeline with `KeyframeAnimator`.
3.  **Trigger on Events:** Start phase animations from state or appearance.
4.  **Design Attention Effects:** Create looping or one-shot emphasis animations.

## 📖 Task Explanations

`PhaseAnimator` cycles a view through a sequence of discrete phases, applying different modifiers in each and animating between them automatically. Give it an array of phases and a content closure receiving the current one, and you have a looping attention effect — a pulsing badge, a wiggling icon — in a handful of lines.

`KeyframeAnimator` gives finer control. You describe independent timelines for several properties, each with its own keyframes, and they run in parallel: scale can bounce while rotation eases and opacity holds. `CubicKeyframe`, `SpringKeyframe`, and `LinearKeyframe` shape each segment, which is how you choreograph motion that a single curve can't express.

Trigger them deliberately. `PhaseAnimator` has a trigger-based initializer that runs the sequence once when a value changes — right for a one-shot reaction like a like button — while the plain initializer loops continuously, right for ambient motion. Choosing wrong is how you end up with something that never stops moving.

Finally, design with restraint, and honour `\.accessibilityReduceMotion` (Day 78) by offering a gentler variant when it's on. These tools make intricate motion cheap to express, which is exactly why it's worth asking whether each animation earns its place — attention effects work because they're rare.

Choose the tool by the shape of the motion, not by novelty. `withAnimation` (Day 66) is still right for a one-shot state change; `PhaseAnimator` is right when the effect is a short sequence of discrete poses; `KeyframeAnimator` is right when several properties must follow independent curves that a single spring can't express. Reaching for keyframes to bounce a button is how these APIs get a reputation for excess. Watch performance on device: a looping `PhaseAnimator` on every row of a list will cost you frames, so drive attention effects from a single visible item and stop them when the view disappears. For a like-button burst, prefer the trigger initializer so the sequence runs once and stops; for a recording indicator, looping is the point. Either way, keep the motion small — a few points of scale, a few degrees of rotation — because large looping motion competes with the content it's meant to emphasise.

## 💡 What You'll Gain

By the end of today, you will choreograph complex, multi-step motion with phase and keyframe animators, expressing effects simple tweens can't.

## 📚 Dictionary for Developers

*   **`PhaseAnimator`:** An animator cycling a view through discrete phases.
*   **`KeyframeAnimator`:** An animator driving properties along keyframed timelines.
*   **Phase:** One discrete step in a multi-stage animation.
*   **Keyframe:** A defined value at a point in an animation timeline.
*   **Trigger-Based Animation:** A sequence that runs once in response to a changing value.
