# Day 6: Types & Protocols - Structs & Properties

## 📝 Today's Tasks

1.  **Design a `struct`:** Model a real entity (e.g. `User`) with stored properties.
2.  **Add Computed Properties:** Expose derived values with a computed `var` (get-only or get/set).
3.  **Use Property Observers:** React to changes with `willSet` and `didSet`.
4.  **Write a Custom Initializer:** Create an instance with the synthesized memberwise initializer, then add your own `init` in an extension.

## 📖 Task Explanations

Model something real — a `User`, an `Order`, a `Recipe` — as a struct with stored properties. Give it only the properties it genuinely needs; small, focused types are far easier to reason about, test, and reuse than one struct that tries to describe everything.

Then add a computed property. Instead of storing `fullName` alongside `firstName` and `lastName`, compute it on demand: it can never fall out of sync with the values it derives from. Computed properties can be get-only or provide a `set` that writes back to the stored properties behind them, which is useful for presenting the same data in a different unit or format.

Property observers react to change. `willSet` runs just before a stored property changes (with `newValue` available) and `didSet` just after (with `oldValue`), which makes them the natural place to trigger a recalculation or log a transition. Note that they don't fire during initialization, and that they belong on stored properties — a computed property has a `set` instead.

Finally, initialization. Swift synthesizes a memberwise initializer for structs, so `User(name:email:)` exists for free — use it first. Then write your own `init` in an `extension`, which is the trick that lets you add a custom initializer *without* losing the synthesized one. While you're here, mark a method that changes the struct's own properties `mutating`, and notice how that makes state changes explicit at every call site.

## 💡 What You'll Gain

By the end of today, you will model data with rich structs that expose derived state and react to change, using Swift's value semantics to keep that state predictable.

## 📚 Dictionary for Developers

*   **Stored Property:** A constant or variable held directly by an instance.
*   **Computed Property:** A property that runs code to produce (or set) a value rather than storing one.
*   **Property Observer:** `willSet`/`didSet` blocks that run before/after a stored property changes.
*   **Memberwise Initializer:** The initializer Swift synthesizes for a struct from its stored properties.
*   **`mutating`:** A keyword marking a method that modifies the value type it belongs to.
