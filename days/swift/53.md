# Day 53: Networking (II) & Architecture - MVVM with @Observable

## 📝 Today's Tasks

1.  **Create a View Model:** Build an `@Observable` view model owning a screen's state.
2.  **Move Logic Out of Views:** Keep the view dumb; put loading and formatting in the view model.
3.  **Isolate to the Main Actor:** Mark the view model `@MainActor` for safe UI updates.
4.  **Depend on Protocols:** Have the view model depend on a repository protocol.

## 📖 Task Explanations

MVVM (Model-View-ViewModel) is the default architecture for SwiftUI. The view model is an `@Observable`, `@MainActor` class that owns a screen's state and logic — fetching, transforming, and formatting data — while the view stays a thin, declarative presentation of that state. Depending on a repository protocol (not a concrete type) keeps the view model testable in isolation. This separation makes each layer's job obvious: models hold data, view models hold logic, views render. Adopting it consistently is what keeps larger apps comprehensible.

## 💡 What You'll Gain

You will structure screens with `@Observable` view models, moving logic out of views and depending on protocols for testability.

## 📚 Dictionary for Developers

*   **MVVM:** An architecture separating Model, View, and ViewModel responsibilities.
*   **View Model:** An observable object holding a screen's state and logic.
*   **Thin View:** A view that only presents state and forwards user intent.
*   **`@MainActor` Isolation:** Ensuring a view model's UI-facing state updates on the main thread.
