# Day 92: Platform Integration - Permissions & Privacy

## 📝 Today's Tasks

1.  **Add Usage Descriptions:** Provide Info.plist purpose strings for each permission.
2.  **Request at the Right Time:** Ask for access in context, when the user expects it.
3.  **Handle Denial:** Degrade gracefully and guide users to Settings.
4.  **Minimize Data Collection:** Request only what the feature genuinely needs.

## 📖 Task Explanations

Apple takes privacy seriously, and so must you. Every sensitive capability — camera, location, contacts, photos — requires a clear purpose string in Info.plist explaining why, or the app crashes when it asks. The best practice is to request access in context, right when the feature needs it and the user understands the reason, rather than up front. When permission is denied, the app must still work in a reduced form and point the user to Settings if they change their mind. Requesting the minimum data necessary isn't just polite; it's required for App Store approval and builds user trust.

## 💡 What You'll Gain

You will handle sensitive permissions correctly and privately — with purpose strings, in-context prompts, and graceful denial handling.

## 📚 Dictionary for Developers

*   **Usage Description:** The Info.plist string explaining why a permission is needed.
*   **In-Context Request:** Asking for permission at the moment it's relevant.
*   **Graceful Degradation:** Keeping the app functional when access is denied.
*   **Data Minimization:** Requesting only the data a feature truly requires.
