# Day 92: Platform Integration - Permissions & Privacy

## 📝 Today's Tasks

1.  **Add Usage Descriptions:** Provide Info.plist purpose strings for each permission.
2.  **Request at the Right Time:** Ask for access in context, when the user expects it.
3.  **Handle Denial:** Degrade gracefully and guide users to Settings.
4.  **Minimize Data Collection:** Request only what the feature genuinely needs.

## 📖 Task Explanations

Add the usage description strings first, because their absence is a crash rather than a warning. Every sensitive capability — camera, microphone, location, photos, contacts — needs a purpose string in the target's Info settings, and the app terminates immediately when it requests access without one. Write them as a specific reason ("to attach photos to your notes"), not a category name; the user reads this string at the exact moment they decide.

Then get the timing right. Ask when the user has just tapped something that obviously needs the permission, not on first launch. A prompt with visible context is granted far more often, and a denial is expensive — you can't re-prompt, only direct the user into Settings.

Handle denial as a supported state rather than a failure. The feature degrades: no camera means offer the photo library, no location means offer manual entry. Include an explanation of what's unavailable and a button that opens Settings with `UIApplication.openSettingsURLString`, so someone who changes their mind isn't hunting through menus.

Finally, request the minimum. Ask for `whenInUse` location rather than `always` unless you truly need it; request limited photo access rather than the full library. This isn't only courtesy — over-requesting draws App Store review scrutiny, inflates your privacy nutrition label, and costs you grants from users who read the prompt carefully.

## 💡 What You'll Gain

By the end of today, you will handle sensitive permissions correctly and privately — with purpose strings, in-context prompts, and graceful denial handling.

## 📚 Dictionary for Developers

*   **Usage Description:** The Info.plist string explaining why a permission is needed.
*   **In-Context Request:** Asking for permission at the moment it's relevant.
*   **Graceful Degradation:** Keeping the app functional when access is denied.
*   **Data Minimization:** Requesting only the data a feature truly requires.
*   **Limited Access:** A partial grant, such as selected photos, that your app must handle.
