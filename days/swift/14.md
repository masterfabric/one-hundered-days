# Day 14: Generics & Error Handling - Protocol-Oriented Programming

## 📝 Today's Tasks

1.  **Model with Small Protocols:** Compose behavior from focused protocols instead of a base class.
2.  **Use Associated Types:** Define a protocol with an `associatedtype` requirement.
3.  **Apply Constraints:** Restrict generic code with `where` clauses on associated types.
4.  **Refactor Inheritance to Protocols:** Replace a class hierarchy with protocol composition.

## 📖 Task Explanations

Start by describing capabilities as small protocols. Instead of a `Vehicle` base class carrying everything, define `Drivable`, `Refuelable`, and `Trackable` separately and let each type adopt only what it genuinely does. Small protocols compose; a large one forces conformers to implement members that make no sense for them.

Then add an `associatedtype`. A protocol with `associatedtype Item` is generic over a type its conformers choose — exactly how `Collection` declares its `Element`. This is what lets one protocol describe a repository of users and a repository of orders without either mentioning the other's type, and it's why such protocols can't be used directly as an `any` type without extra work.

Constrain that generality with `where` clauses. `extension Repository where Item: Identifiable` adds behaviour only to conformers whose item type can be identified, and a generic function can require `where T.Item == User`. Constraints are how protocol-oriented code stays precise: capabilities are declared where they're needed rather than assumed everywhere.

Finally, take a class hierarchy you have and refactor it. Replace the base class with one or more protocols, move the shared implementations into protocol extensions, and turn the subclasses into structs adopting what they need. What you gain is value semantics, no fragile base-class coupling, and types that are trivial to fake in tests — which is why this composition-over-inheritance shift changes how you architect whole applications.

## 💡 What You'll Gain

By the end of today, you will design with protocol composition and associated types, replacing brittle inheritance with flexible, testable abstractions.

## 📚 Dictionary for Developers

*   **POP:** Protocol-oriented programming: composing behavior from protocols over inheritance.
*   **`associatedtype`:** A placeholder type a protocol declares for conformers to specify.
*   **Composition:** Building behavior by combining multiple small protocols.
*   **`where` Clause:** A constraint refining when generic code applies.
*   **Fragile Base Class:** The problem where changing a superclass silently breaks its subclasses.
