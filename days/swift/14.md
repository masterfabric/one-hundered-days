# Day 14: Generics & Error Handling - Protocol-Oriented Programming

## 📝 Today's Tasks

1.  **Model with Small Protocols:** Compose behavior from focused protocols instead of a base class.
2.  **Use Associated Types:** Define a protocol with an `associatedtype` requirement.
3.  **Apply Constraints:** Restrict generic code with `where` clauses on associated types.
4.  **Refactor Inheritance to Protocols:** Replace a class hierarchy with protocol composition.

## 📖 Task Explanations

Protocol-oriented programming (POP) is Swift's signature paradigm. Rather than modeling with a rigid class tree, you describe capabilities as small protocols, give them default implementations, and compose them onto value types. Associated types let a protocol be generic over a type it works with (the same idea that powers `Collection`). The result is highly reusable, testable code with no fragile base-class coupling. Learning to see designs as compositions of protocols — instead of inheritance chains — changes how you architect entire applications.

## 💡 What You'll Gain

You will design with protocol composition and associated types, replacing brittle inheritance with flexible, testable abstractions.

## 📚 Dictionary for Developers

*   **POP:** Protocol-oriented programming: composing behavior from protocols over inheritance.
*   **`associatedtype`:** A placeholder type a protocol declares for conformers to specify.
*   **Composition:** Building behavior by combining multiple small protocols.
*   **`where` Clause:** A constraint refining when generic code applies.
