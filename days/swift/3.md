# Day 3: Swift Fundamentals - Optionals & Safe Unwrapping

## 📝 Today's Tasks

1.  **Declare an Optional:** Declare `var name: String?` and understand it means "a `String` or `nil`".
2.  **Unwrap with `if let`:** Safely bind the wrapped value with `if let name { ... }` shorthand.
3.  **Use `guard let`:** Exit early with `guard let name else { return }` to keep the happy path unindented.
4.  **Apply the Nil-Coalescing Operator:** Provide a fallback with `name ?? "Guest"`.

## 📖 Task Explanations

Optionals are Swift's compile-time answer to the billion-dollar null-reference mistake. An `Optional<Wrapped>` (written `Wrapped?`) is an enum with two cases: `.some(value)` or `.none`. Because the type system forces you to acknowledge absence before you can use a value, whole classes of crashes simply cannot compile. You unwrap safely with `if let` and `guard let`, supply defaults with `??`, and reserve force-unwrap (`!`) for the rare cases where `nil` is a genuine programmer error. Mastering optionals is mastering safety in Swift.

## 💡 What You'll Gain

You will handle the presence and absence of values safely and idiomatically, writing code that the compiler proves cannot crash on `nil`.

## 📚 Dictionary for Developers

*   **Optional:** A type that either holds a value (`.some`) or holds nothing (`.none`/`nil`).
*   **Unwrapping:** Extracting the concrete value from inside an optional.
*   **`guard let`:** A statement that unwraps or exits scope early, keeping the main path flat.
*   **Nil-Coalescing (`??`):** An operator that supplies a default when the optional is `nil`.
