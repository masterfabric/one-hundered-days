# Day 3: Swift Fundamentals - Optionals & Safe Unwrapping

## 📝 Today's Tasks

1.  **Declare an Optional:** Declare `var name: String?` and understand it means "a `String` or `nil`".
2.  **Unwrap with `if let`:** Safely bind the wrapped value with `if let name { ... }` shorthand.
3.  **Use `guard let`:** Exit early with `guard let name else { return }` to keep the happy path unindented.
4.  **Apply the Nil-Coalescing Operator:** Provide a fallback with `name ?? "Guest"`.

## 📖 Task Explanations

Declare `var name: String?` and read the type out loud: a `String` *or* `nil`. An `Optional<Wrapped>` is really an enum with two cases, `.some(value)` and `.none`, and the `?` is just sugar for it. Because the type system forces you to acknowledge absence before you can use the value, whole classes of null-reference crashes simply cannot compile.

Unwrap it safely with `if let name { ... }` — the shorthand form, where you don't repeat the name. Inside the braces, `name` is a plain non-optional `String`; outside, it's still optional. Try calling `.count` on the optional directly to see the compiler refuse, then use optional chaining (`name?.count`) and note that the result is itself optional.

`guard let name else { return }` does the same unwrapping but inverts the shape: it handles the failure case first and exits, leaving the rest of the function flat and unindented. Rewrite one of your `if let` blocks as a `guard` and compare them. Guards are the idiomatic choice at the top of a function where a missing value means there is nothing to do.

Round it off with the nil-coalescing operator: `name ?? "Guest"` yields the wrapped value or a fallback, and the result is non-optional. Between `if let`, `guard let`, and `??` you have everything you need — save force-unwrap (`!`) for the rare case where `nil` would be a genuine programmer error, since it crashes rather than recovering.

## 💡 What You'll Gain

By the end of today, you will handle the presence and absence of values safely and idiomatically, writing code that the compiler proves cannot crash on `nil`.

## 📚 Dictionary for Developers

*   **Optional:** A type that either holds a value (`.some`) or holds nothing (`.none`/`nil`).
*   **Unwrapping:** Extracting the concrete value from inside an optional.
*   **`guard let`:** A statement that unwraps or exits scope early, keeping the main path flat.
*   **Nil-Coalescing (`??`):** An operator that supplies a default when the optional is `nil`.
*   **Optional Chaining:** Calling a member on an optional with `?`, producing an optional result.
