# Day 85: Performance & Concurrency in Practice - App Launch & Memory

## 📝 Today's Tasks

1.  **Optimize Launch Time:** Defer non-essential work off the startup path.
2.  **Reduce Memory Footprint:** Release large resources and avoid retain cycles.
3.  **Handle Memory Warnings:** Respond to memory pressure appropriately.
4.  **Profile Real Devices:** Measure on-device, where results differ from the Simulator.

## 📖 Task Explanations

Launch time is the first thing every user measures, whether or not they think of it that way. Audit what runs before the first frame — analytics SDK setup, prefetching, migrations, cache warming — and defer everything that isn't needed to draw the initial screen. Move it into a `.task` on the first view or a background task after launch, and measure with the App Launch instrument rather than a stopwatch.

Memory is the slower-burning problem. Release large images and buffers when their screen goes away, avoid the retain cycles from Day 15, and be wary of caches without a bound — an unlimited image cache is a leak with a friendlier name. `NSCache` evicts under pressure, which is usually the right default.

Respond to memory pressure when it comes. The system notifies you before it starts killing apps, and dropping caches and offscreen resources at that moment is often the difference between a hiccup and a termination the user reads as a crash.

Finally, profile on real hardware, and preferably on the oldest device you support. The Simulator uses your Mac's CPU and memory, so it flatters everything — GPU-bound work especially, which now includes Liquid Glass rendering on iOS 26. A screen that scrolls perfectly in the Simulator and stutters on a real phone is the normal outcome, not an unlucky one.

## 💡 What You'll Gain

By the end of today, you will optimize launch time and memory footprint and profile on real devices, delivering an app that feels fast and stays lean.

## 📚 Dictionary for Developers

*   **Launch Time:** How long the app takes to become usable at startup.
*   **Memory Footprint:** The amount of memory an app consumes.
*   **Memory Pressure:** A system signal that memory is scarce.
*   **On-Device Profiling:** Measuring performance on real hardware, not the Simulator.
*   **`NSCache`:** A cache that automatically evicts entries when the system is short of memory.
