# Day 85: Performance & Concurrency in Practice - App Launch & Memory

## 📝 Today's Tasks

1.  **Optimize Launch Time:** Defer non-essential work off the startup path.
2.  **Reduce Memory Footprint:** Release large resources and avoid retain cycles.
3.  **Handle Memory Warnings:** Respond to memory pressure appropriately.
4.  **Profile Real Devices:** Measure on-device, where results differ from the Simulator.

## 📖 Task Explanations

The first and lasting impressions of an app are its launch speed and memory behavior. Fast launch means deferring anything non-essential (analytics setup, prefetching) off the critical startup path so the first screen appears quickly. A lean memory footprint means releasing large images and buffers when not visible, avoiding the retain cycles you learned to spot, and responding to system memory pressure by shedding caches. Crucially, you must profile on real devices — especially with Liquid Glass rendering on iOS 26+ — because the Simulator's performance and memory characteristics differ from actual hardware.

## 💡 What You'll Gain

You will optimize launch time and memory footprint and profile on real devices, delivering an app that feels fast and stays lean.

## 📚 Dictionary for Developers

*   **Launch Time:** How long the app takes to become usable at startup.
*   **Memory Footprint:** The amount of memory an app consumes.
*   **Memory Pressure:** A system signal that memory is scarce.
*   **On-Device Profiling:** Measuring performance on real hardware, not the Simulator.
