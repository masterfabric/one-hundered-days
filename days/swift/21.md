# Day 21: SwiftUI Basics - The View Protocol

## 📝 Today's Tasks

1.  **Create a SwiftUI Project:** Start a new iOS 26 App in Xcode 27 and inspect the `@main` App struct.
2.  **Read a `View`:** Understand that a `View` is a value type with a `body` computed property.
3.  **Render `Text` and `Image`:** Display text and an SF Symbol image.
4.  **Use `#Preview`:** Live-preview the view in the canvas with the `#Preview` macro.

## 📖 Task Explanations

SwiftUI is declarative: you describe what the UI should look like for a given state, and the framework figures out how to render and update it. Every screen is a `View`, which is a lightweight value type whose `body` returns more views — a tree that SwiftUI diffs and re-renders efficiently when state changes. This is a mental shift from imperative UIKit, where you mutate views by hand. The `#Preview` macro renders your view live in Xcode's canvas without launching the Simulator, giving you an instant feedback loop that makes UI development fast and iterative.

## 💡 What You'll Gain

You will understand SwiftUI's declarative model and the `View` protocol, and use live previews to iterate on UI in seconds.

## 📚 Dictionary for Developers

*   **Declarative UI:** Describing the UI as a function of state rather than mutating it imperatively.
*   **`View`:** A value type whose `body` describes a piece of UI.
*   **`body`:** The computed property returning a view's content.
*   **`#Preview`:** A macro that renders a view live in Xcode's canvas.
