# Day 21: SwiftUI Basics - The View Protocol

## 📝 Today's Tasks

1.  **Create a SwiftUI Project:** Start a new iOS App in the **latest stable Xcode** (using a supported deployment target) and inspect the `@main` App struct.
2.  **Read a `View`:** Understand that a `View` is a value type with a `body` computed property.
3.  **Render `Text` and `Image`:** Display text and an SF Symbol image.
4.  **Use `#Preview`:** Live-preview the view in the canvas with the `#Preview` macro.

## 📖 Task Explanations

Create a new iOS App in Xcode with the SwiftUI interface, then open the file marked `@main`. That struct conforms to `App` and its `body` returns a `Scene` — usually a `WindowGroup` wrapping your first view. That's the whole entry point: no `AppDelegate`, no storyboard, no `main.swift`, just a value describing the app's structure.

Now read `ContentView` carefully, because it explains SwiftUI's core idea. A `View` is a *value type* — a struct — with a `body` computed property returning more views. Your views are lightweight descriptions that SwiftUI creates, diffs, and throws away constantly; they are not long-lived objects you mutate. That's the mental shift from UIKit, where you hold references to views and change them by hand.

Render something. `Text("Hello")` and `Image(systemName: "star.fill")` are enough, and putting them in a `VStack` gives you a two-view hierarchy. Note that `body` returns `some View` — an opaque type, from Day 11 — which lets you return whatever complicated nested type your view tree produces without ever writing it out.

Finally, use `#Preview`. The macro renders your view live in the canvas without launching the Simulator, and you can declare several previews with different sample data. The tight feedback loop it gives you is a genuine part of the workflow, not a nicety: previews are fastest when views are small and take their data as inputs, which is a habit worth forming from day one.

## 💡 What You'll Gain

By the end of today, you will understand SwiftUI's declarative model and the `View` protocol, and use live previews to iterate on UI in seconds.

## 📚 Dictionary for Developers

*   **Declarative UI:** Describing the UI as a function of state rather than mutating it imperatively.
*   **`View`:** A value type whose `body` describes a piece of UI.
*   **`body`:** The computed property returning a view's content.
*   **`#Preview`:** A macro that renders a view live in Xcode's canvas.
*   **`Scene`:** A container declaring a unit of your app's UI, such as a `WindowGroup`.
*   **`some View`:** An opaque return type letting `body` hide its concrete view type.
