# Day 91: Platform Integration - Notifications

## 📝 Today's Tasks

1.  **Request Authorization:** Ask permission for notifications correctly.
2.  **Schedule Local Notifications:** Post a local notification with `UNUserNotificationCenter`.
3.  **Handle Taps:** Route a tapped notification into the app via deep linking.
4.  **Register for Push:** Request notification authorization, register for APNs, and print the device token.

## 📖 Task Explanations

Request authorization with `UNUserNotificationCenter.current().requestAuthorization(options:)`, and think about when. You get one prompt: deny it and you can't ask again, only send the user to Settings. So ask after the user has done something that makes notifications obviously useful, ideally after a short in-app explanation of what you'll send — not on first launch before they know what the app does.

Then schedule a local notification: build a `UNMutableNotificationContent`, choose a trigger (interval, calendar, or location), and add the request. Local notifications need no server at all, which covers reminders, timers, and scheduled prompts — a surprising share of what apps actually send.

Handle the tap by routing rather than just launching. Put an identifier in the notification's `userInfo`, read it in your notification delegate, and append the matching route to the navigation path. Opening the app to its default screen after a notification about something specific is a small failure the user notices every time.

Finally, register for remote push: after authorization, call `registerForRemoteNotifications()` and implement the delegate method that receives the device token. That token is what your server sends to APNs to reach this installation. The on-device handling is identical to local notifications — the difference is entirely on the server side. Design what you send as carefully as how: notifications are the fastest way to get your permission revoked.

## 💡 What You'll Gain

By the end of today, you will request permission and schedule local notifications that route into your app, and understand how remote push fits in.

## 📚 Dictionary for Developers

*   **`UNUserNotificationCenter`:** The API for scheduling and handling notifications.
*   **Authorization:** The user's granted permission to send notifications.
*   **Notification Trigger:** The condition (time, calendar, location) firing a notification.
*   **APNs:** Apple Push Notification service for remote pushes.
*   **Device Token:** The per-install identifier APNs uses to route a push to one device.
