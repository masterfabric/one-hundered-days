# Day 91: Platform Integration - Notifications

## 📝 Today's Tasks

1.  **Request Authorization:** Ask permission for notifications correctly.
2.  **Schedule Local Notifications:** Post a local notification with `UNUserNotificationCenter`.
3.  **Handle Taps:** Route a tapped notification into the app via deep linking.
4.  **Understand Push:** Learn the shape of remote push (APNs) at a high level.

## 📖 Task Explanations

Notifications re-engage users, but they demand care. You must request authorization respectfully (and handle denial gracefully), then schedule local notifications through `UNUserNotificationCenter` with triggers based on time, calendar, or location. Handling a tap means routing the user to the relevant screen — reusing your deep-linking infrastructure. Remote push notifications add a server and Apple Push Notification service (APNs), but the on-device handling is similar. Done well, notifications are helpful; done carelessly, they get your app's permission revoked, so thoughtful design matters as much as the API.

## 💡 What You'll Gain

You will request permission and schedule local notifications that route into your app, and understand how remote push fits in.

## 📚 Dictionary for Developers

*   **`UNUserNotificationCenter`:** The API for scheduling and handling notifications.
*   **Authorization:** The user's granted permission to send notifications.
*   **Notification Trigger:** The condition (time, calendar, location) firing a notification.
*   **APNs:** Apple Push Notification service for remote pushes.
