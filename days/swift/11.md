# Day 11: Generics & Error Handling - Generics

## 📝 Today's Tasks

1.  **Write a Generic Function:** Implement `func swapValues<T>(_ a: inout T, _ b: inout T)`.
2.  **Create a Generic Type:** Build a `Stack<Element>` with push/pop.
3.  **Add Type Constraints:** Constrain a generic with `<T: Comparable>`.
4.  **Understand `some` vs `any`:** Compare opaque return types (`some`) with existentials (`any`).

## 📖 Task Explanations

Generics let you write code once that works for many types while staying fully type-safe. A `Stack<Element>` is the same logic whether it holds `Int`s or `User`s, with no casting and no loss of type information. Type constraints (`<T: Comparable>`) let a generic require capabilities from its type parameter. Swift provides two related tools: `some` (opaque types, Swift 5.1+) returns an opaque concrete type (fast, no boxing) while `any` (explicit existentials, Swift 5.6+) stores a type-erased existential (flexible, slightly costlier). Choosing between them deliberately is a hallmark of fluent Swift.

## 💡 What You'll Gain

You will write reusable, type-safe code with generics and constraints, and understand the performance trade-off between `some` and `any`.

## 📚 Dictionary for Developers

*   **Generic:** Code parameterized over a type it operates on.
*   **Type Parameter:** A placeholder type (e.g. `T`) resolved at the call site.
*   **Type Constraint:** A requirement that a generic's type conform to a protocol.
*   **Opaque Type (`some`):** A return type that hides its concrete identity while staying static.
