# Day 11: Generics & Error Handling - Generics

## 📝 Today's Tasks

1.  **Write a Generic Function:** Implement `func swapValues<T>(_ a: inout T, _ b: inout T)`.
2.  **Create a Generic Type:** Build a `Stack<Element>` with push/pop.
3.  **Add Type Constraints:** Constrain a generic with `<T: Comparable>`.
4.  **Compare `some` and `any`:** Write one function returning `some Shape` and one returning `any Shape`, then call both.

## 📖 Task Explanations

Write `func swapValues<T>(_ a: inout T, _ b: inout T)` and call it with `Int`s, then with `String`s. The same body serves both because `T` is a placeholder resolved at each call site, and — unlike casting through `Any` — no type information is lost: the compiler still knows exactly what came out.

Then build a generic type. A `Stack<Element>` with `push` and `pop` is the same logic whether it holds `Int`s or `User`s; declare the storage as `private var items: [Element]` and let the type parameter flow through. Notice that `pop()` naturally returns `Element?`, since an empty stack has nothing to give — generics and optionals compose without any special handling.

Constraints let a generic demand capabilities. `func maximum<T: Comparable>(_ values: [T]) -> T?` needs `<` to exist, so it requires `Comparable`; without the constraint the body simply won't compile. Constraints are what keep generics type-safe rather than a loophole: you get flexibility over types, but only over types that can actually do the work.

Finally, write two functions, one returning `some Shape` and one returning `any Shape`, and call both. `some` (opaque types, Swift 5.1+) returns one specific concrete type that the caller can't see but the compiler still knows, so there's no boxing — this is why every SwiftUI `body` is declared `some View`. `any` (Swift 5.6+) stores a type-erased existential, which is more flexible when a collection must hold several different conforming types, at a small runtime cost.

## 💡 What You'll Gain

By the end of today, you will write reusable, type-safe code with generics and constraints, and understand the performance trade-off between `some` and `any`.

## 📚 Dictionary for Developers

*   **Generic:** Code parameterized over a type it operates on.
*   **Type Parameter:** A placeholder type (e.g. `T`) resolved at the call site.
*   **Type Constraint:** A requirement that a generic's type conform to a protocol.
*   **Opaque Type (`some`):** A return type that hides its concrete identity while staying static.
*   **Existential Box:** The runtime container holding a value whose concrete type is erased behind `any`.
