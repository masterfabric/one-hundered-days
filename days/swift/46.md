# Day 46: Networking (I) - URLSession & async

## 📝 Today's Tasks

1.  **Fetch Data:** Call `try await URLSession.shared.data(from:)`.
2.  **Inspect the Response:** Cast to `HTTPURLResponse` and read the status code.
3.  **Handle Transport Errors:** Catch networking errors and map them to your error type.
4.  **Load in `.task`:** Trigger the fetch from a view's `.task` modifier.

## 📖 Task Explanations

Networking in modern Swift is `async`/`await` end-to-end. `URLSession`'s async `data(from:)` suspends until the response arrives without blocking a thread, returning the raw data and a response you inspect for the HTTP status. SwiftUI's `.task` modifier is the natural trigger: it starts the fetch when the view appears and cancels it automatically when the view disappears. Wrapping transport failures into your own error type keeps error handling clean at the call site. This is the backbone every networked app is built on.

## 💡 What You'll Gain

You will fetch data over the network with async `URLSession`, triggered and cancelled correctly by SwiftUI's `.task`.

## 📚 Dictionary for Developers

*   **`URLSession`:** Apple's API for making HTTP requests.
*   **`HTTPURLResponse`:** The response type exposing status code and headers.
*   **`.task`:** A view modifier running async work tied to the view's lifetime.
*   **Transport Error:** A failure at the network layer (timeout, no connection).
