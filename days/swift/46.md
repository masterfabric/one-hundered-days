# Day 46: Networking (I) - URLSession & async

## 📝 Today's Tasks

1.  **Fetch Data:** Call `try await URLSession.shared.data(from:)`.
2.  **Inspect the Response:** Cast to `HTTPURLResponse` and read the status code.
3.  **Handle Transport Errors:** Catch networking errors and map them to your error type.
4.  **Load in `.task`:** Trigger the fetch from a view's `.task` modifier.

## 📖 Task Explanations

Start with the request itself: `let (data, response) = try await URLSession.shared.data(from: url)`. One line replaces a completion handler, a capture list, and a manual dispatch back to the main thread. The call suspends until the response arrives without blocking a thread, and failures arrive as thrown errors, so the `do`/`catch` you already know covers them.

Then inspect what came back. `response` is a `URLResponse`, so cast it with `guard let http = response as? HTTPURLResponse` and read `http.statusCode`. This step is not optional in practice: a 404 or a 500 is a perfectly successful *transport*, so `URLSession` does not throw for it — your code has to check, or you'll cheerfully try to decode an error page as your model.

Map failures into your own error type. Catch `URLError` and translate the cases you care about — `.notConnectedToInternet`, `.timedOut`, `.cancelled` — into something like `NetworkError.offline` or `.timeout`. Doing the translation at the network layer means every caller upstream deals with one small, meaningful set of errors instead of the whole `URLError` surface.

Finally, trigger the fetch from `.task { await load() }` on the view. It starts when the view appears and, critically, cancels automatically when the view disappears — so scrolling past a screen doesn't leave a request running. Use `.task(id:)` when the fetch depends on a value that can change, and never `onAppear` plus a detached `Task`, which leaks work the moment the user navigates away.

## 💡 What You'll Gain

By the end of today, you will fetch data over the network with async `URLSession`, triggered and cancelled correctly by SwiftUI's `.task`.

## 📚 Dictionary for Developers

*   **`URLSession`:** Apple's API for making HTTP requests.
*   **`HTTPURLResponse`:** The response type exposing status code and headers.
*   **`.task`:** A view modifier running async work tied to the view's lifetime.
*   **Transport Error:** A failure at the network layer (timeout, no connection).
*   **Task Cancellation:** Automatic teardown of in-flight async work when its owner goes away.
