# Day 30: Layout & Composition - Adaptive & Responsive UI

## 📝 Today's Tasks

1.  **Read the Size Class:** Adapt layout using `@Environment(\.horizontalSizeClass)`.
2.  **Use `ViewThatFits`:** Let SwiftUI pick the first layout that fits with `ViewThatFits`.
3.  **Support iPad & Orientation:** Design a layout that reflows between compact and regular widths.
4.  **Preview Multiple Devices:** Add previews for different device sizes.

## 📖 Task Explanations

Read the size class first: `@Environment(\.horizontalSizeClass) private var hSizeClass`. It reports `.compact` or `.regular` — a coarse description of available width that covers iPhone portrait, iPhone landscape, iPad full-screen, and iPad multitasking without you ever checking a device model. Branch on it to swap a `VStack` for an `HStack`, or to show a sidebar instead of a tab bar.

`ViewThatFits` handles the finer-grained cases automatically. Give it several candidate layouts, from widest to narrowest, and it renders the first one that fits the space available. It's the cleanest way to degrade a horizontal row into a stacked column, or a long button label into a short one, without writing any measurement code at all.

Then design one screen that genuinely reflows. Take a detail view and make it a single column at compact width and two columns at regular, with `.containerRelativeFrame` or an adaptive grid handling the in-between. Rotate the Simulator and try iPad Split View — landscape and multitasking are where hard-coded assumptions surface fastest.

Finally, add previews for several devices, plus a dark-mode and a large-Dynamic-Type variant. Previews cost nothing to run and catch layout regressions before you build to a device, which is the whole point: one codebase that feels native on every screen size, verified continuously rather than checked once at the end.

## 💡 What You'll Gain

By the end of today, you will build responsive layouts that adapt across iPhone, iPad, and orientations from a single codebase.

## 📚 Dictionary for Developers

*   **Size Class:** A coarse measure (`compact`/`regular`) of available space.
*   **`ViewThatFits`:** A container that picks the first child layout that fits.
*   **Responsive Design:** UI that reflows to fit different screen sizes and orientations.
*   **Regular/Compact:** The two size-class values driving adaptive decisions.
*   **Split View:** iPad multitasking that runs two apps side by side, changing your size class.
