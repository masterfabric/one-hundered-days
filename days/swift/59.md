# Day 59: Persistence with SwiftData - Migrations & Schema

## 📝 Today's Tasks

1.  **Version the Schema:** Define versioned schemas for your models.
2.  **Write a Migration Plan:** Provide a `SchemaMigrationPlan` for lightweight/custom migrations.
3.  **Handle Data Evolution:** Add, rename, or transform properties across versions.
4.  **Test the Upgrade Path:** Verify existing data survives a schema change.

## 📖 Task Explanations

Real apps evolve, and so must their data. SwiftData supports schema versioning: you declare each version of your models and a `SchemaMigrationPlan` describing how to move between them. Simple additions can migrate automatically (lightweight), while renames or transformations need a custom migration stage. Getting this right matters enormously — a broken migration can lose or corrupt a user's data on update. Testing the upgrade path with realistic existing data before shipping is a non-negotiable professional habit that beginners often skip until it bites them.

## 💡 What You'll Gain

You will evolve a SwiftData schema safely with versioning and migrations, protecting users' existing data across app updates.

## 📚 Dictionary for Developers

*   **Schema:** The definition of your persistent model structure.
*   **Migration:** The process of moving stored data to a new schema version.
*   **Lightweight Migration:** An automatic migration for simple, inferable changes.
*   **`SchemaMigrationPlan`:** The declaration of how to migrate between schema versions.
