# Day 9: Types & Protocols - Protocols & Conformance

## 📝 Today's Tasks

1.  **Declare a Protocol:** Define a protocol with required properties and methods.
2.  **Conform a Type:** Make a `struct` conform and implement the requirements.
3.  **Use Protocol as a Type:** Accept `any Protocol` as a parameter (existential).
4.  **Adopt Standard Protocols:** Conform to `Equatable`, `Hashable`, and `Comparable`.

## 📖 Task Explanations

Declare a protocol with the properties and methods a conforming type must supply. A protocol is a contract about *what*, never *how* — it can require a `var` (specifying `{ get }` or `{ get set }`), a method, an initializer, or a subscript, but it supplies no implementation of its own.

Make a struct conform and implement the requirements. The compiler checks conformance at compile time, so a missing member is an error, not a runtime surprise. Put the conformance in its own `extension` when the type is non-trivial; it keeps the type's core definition readable and groups everything the protocol needs in one place.

Then use the protocol as a type. A parameter of type `any Shape` accepts any conforming value, boxed inside an existential so the concrete type is hidden. This is how you write functions against capabilities rather than concrete types — the foundation of testable code, since a test can pass a fake conformer where production passes the real one.

Finally, adopt the standard-library protocols, which unlock enormous amounts of behaviour for free. Conform to `Equatable` and `==` works; add `Hashable` and your type can live in a `Set` or serve as a dictionary key; add `Comparable` and `sorted()` just works. For most structs Swift synthesizes these automatically when every stored property already conforms, so the whole thing is often a single line in an extension.

## 💡 What You'll Gain

By the end of today, you will define contracts with protocols and conform your types to them, unlocking abstraction and the free behavior that standard protocols provide.

## 📚 Dictionary for Developers

*   **Protocol:** A contract specifying properties and methods a type must implement.
*   **Conformance:** A type fulfilling a protocol's requirements.
*   **Existential (`any`):** A boxed value known only by the protocol it conforms to.
*   **`Equatable`/`Hashable`:** Standard protocols enabling equality checks and hashing.
*   **Synthesized Conformance:** Compiler-generated protocol implementations, as for `Equatable` on simple structs.
