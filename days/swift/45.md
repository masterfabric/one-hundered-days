# Day 45: User Input & Forms - Gestures

## 📝 Today's Tasks

1.  **Add Tap & Long-Press:** Attach `.onTapGesture` and `.onLongPressGesture`.
2.  **Drag Views:** Track movement with `DragGesture` and update offset state.
3.  **Compose Gestures:** Combine gestures with `.simultaneously`, `.sequenced`, `.exclusively`.
4.  **Animate Gesture State:** Use `@GestureState` for transient interaction state.

## 📖 Task Explanations

Start with the two discrete gestures. `.onTapGesture` runs a closure on tap and takes a `count:` if you want double-taps; `.onLongPressGesture` fires after a press duration you can set. Attach them to a shape or card and note that they apply to the view's hit-testing area, so a `Color.clear` background or `.contentShape(.rect)` is often what you need to make the whole row tappable rather than just its text.

Continuous gestures come from `DragGesture`. Attach it with `.gesture(...)`, store `value.translation` in state from `onChanged`, apply it with `.offset(...)`, and decide in `onEnded` whether to snap back or commit. That single pattern — read translation, offset the view, resolve on end — is the basis of drag-to-dismiss, swipe-to-delete, and reorderable cards. `MagnifyGesture` and `RotateGesture` follow the same shape for pinch and twist.

Real interactions usually need more than one gesture at a time, which is what the composition operators are for. `.simultaneously(with:)` runs two gestures together — pinch and rotate on a photo; `.sequenced(before:)` requires one to succeed first, as in long-press-then-drag to pick up a card; `.exclusively(before:)` lets the first gesture to recognise win. Build one of each so the differences stick.

Finally, prefer `@GestureState` over plain `@State` for anything that only exists mid-gesture. It resets to its initial value automatically the moment the gesture ends or is cancelled, so a dragged card returns home without you writing any cleanup — and it's much harder to leave the UI stuck in a half-dragged state. Wrap the reset in `withAnimation` and you get the fluid, direct-manipulation feel that defines a good iOS app.

## 📚 Dictionary for Developers

*   **Gesture:** A recognizer for user touch interactions.
*   **`DragGesture`:** A gesture tracking continuous movement.
*   **Gesture Composition:** Combining gestures simultaneously, sequentially, or exclusively.
*   **`@GestureState`:** State tied to an in-progress gesture that auto-resets.
*   **Translation:** The offset from a drag's start point to its current point.
*   **Hit Testing:** How SwiftUI decides which view receives a touch.
