# Day 97: Release & CI/CD - Signing, Provisioning & TestFlight

## 📝 Today's Tasks

1.  **Understand Code Signing:** Grasp certificates, identifiers, and provisioning profiles.
2.  **Use Automatic Signing:** Let Xcode manage signing where possible.
3.  **Distribute via TestFlight:** Upload a build and invite testers.
4.  **Gather Beta Feedback:** Collect crash reports and tester feedback before release.

## 📖 Task Explanations

Apple requires every app to be code-signed, which ties a build to your developer identity via certificates and provisioning profiles that authorize specific apps and devices. Xcode's automatic signing handles most of this, but understanding the pieces helps when it breaks. TestFlight is Apple's beta distribution: you upload a build and invite testers to try it, gathering real-world crash reports and feedback before the public release. A TestFlight beta phase catches issues your own testing missed and is a standard, expected step in a professional release process rather than shipping straight to the store.

## 💡 What You'll Gain

You will navigate code signing and run a TestFlight beta, distributing builds to testers and gathering feedback before public release.

## 📚 Dictionary for Developers

*   **Code Signing:** Cryptographically tying a build to a developer identity.
*   **Provisioning Profile:** A file authorizing an app to run on specific devices.
*   **TestFlight:** Apple's platform for distributing beta builds to testers.
*   **Beta Feedback:** Tester reports and crashes gathered before release.
