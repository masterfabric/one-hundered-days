# Day 98: Release & CI/CD - Continuous Integration

## 📝 Today's Tasks

1.  **Automate Builds & Tests:** Run build and test on every push via CI.
2.  **Write a GitHub Actions Workflow:** Configure a macOS runner to `xcodebuild test`.
3.  **Configure an Xcode Cloud Workflow:** Set up one Xcode Cloud workflow and run it against your repo.
4.  **Enforce Quality Gates:** Block merges when tests or linting fail.

## 📖 Task Explanations

Set up CI to build and test on every push. The value is not the automation itself but the elimination of "works on my machine": a clean checkout on a machine with none of your local state is the only honest test of whether the project actually builds.

Write the workflow. A GitHub Actions job on a `macos-latest` runner checks out the code, selects an Xcode version explicitly (the default drifts as runners update), resolves package dependencies, and runs `xcodebuild test` with a destination naming a Simulator. Pin the Xcode and Simulator versions so a green build today doesn't fail tomorrow for reasons unrelated to your code.

Xcode Cloud is Apple's alternative, configured from within Xcode and integrated with App Store Connect, TestFlight, and signing. It handles the Apple-specific parts with far less configuration; GitHub Actions gives you more control and runs alongside the rest of your tooling. Try one workflow in each and pick on that basis rather than on principle.

Finally, enforce the gate. Mark the test job as a required status check so a pull request cannot merge while it's red, and add linting alongside it. This is where the testing discipline from Days 71–80 pays off at team scale: a suite that runs automatically on every change is a guardrail, while one people run when they remember is decoration.

## 💡 What You'll Gain

By the end of today, you will automate build and test on every push with CI, enforcing quality gates that catch regressions before merge.

## 📚 Dictionary for Developers

*   **Continuous Integration:** Automatically building and testing on each change.
*   **GitHub Actions:** A CI system running workflows on hosted runners.
*   **Xcode Cloud:** Apple's native CI/CD service for Xcode projects.
*   **Quality Gate:** A required check that must pass before code merges.
*   **Required Status Check:** A CI job that must pass before a pull request can merge.
