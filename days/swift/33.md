# Day 33: State & Data Flow - @Bindable & Two-Way Model Binding

## 📝 Today's Tasks

1.  **Bind to an `@Observable`:** Use `@Bindable` to get bindings into an observable model's properties.
2.  **Wire Up a Form:** Bind text fields to model properties with `$model.property`.
3.  **Pass Models to Children:** Share an observable model down the view tree.
4.  **Distinguish `@State` vs `@Bindable`:** Know when each wrapper is appropriate.

## 📖 Task Explanations

Start from an `@Observable` model that a view receives rather than creates. Declaring it `@Bindable var model: Recipe` gives you the `$` projection on that model, so `$model.title` is a `Binding<String>` you can hand to a control. Without `@Bindable` you can read the model's properties but you can't bind to them, which is the exact gap this wrapper fills.

Wire up a form with it. `TextField("Title", text: $model.title)` writes straight into the model, and because the model is observed, every other view reading `title` updates too. There is no local copy to keep in sync and no save step — the editor mutates the shared source of truth directly, which is usually what you want for an inline edit screen.

Passing models down needs no wrapper at all in the read-only case: a child that only displays data takes a plain `let model: Recipe` and still re-renders when the model changes, because observation tracks the property reads wherever they happen. Add `@Bindable` in the child only when that child needs to write.

Finally, get the ownership rule straight, because it's the one people trip on. `@State` when this view creates the model and should keep it alive; `@Bindable` when the model arrives from elsewhere and you need bindings into it; `@Environment` when it's a shared service injected from above. Ask "who creates this and how long should it live?" and the right wrapper follows.

## 💡 What You'll Gain

By the end of today, you will create two-way bindings into observable models with `@Bindable`, enabling clean, direct editing of shared state in forms and detail screens.

## 📚 Dictionary for Developers

*   **`@Bindable`:** A wrapper exposing bindings to an `@Observable` model's properties.
*   **Two-Way Binding:** A connection letting a control both read and write a value.
*   **Model Ownership:** Which view is responsible for creating and holding a model.
*   **Editor View:** A view that mutates a shared model through bindings.
*   **Property Wrapper:** A type that adds behavior to a property, such as `@State` or `@Bindable`.
