# Day 33: State & Data Flow - @Bindable & Two-Way Model Binding

## 📝 Today's Tasks

1.  **Bind to an `@Observable`:** Use `@Bindable` to get bindings into an observable model's properties.
2.  **Wire Up a Form:** Bind text fields to model properties with `$model.property`.
3.  **Pass Models to Children:** Share an observable model down the view tree.
4.  **Distinguish `@State` vs `@Bindable`:** Know when each wrapper is appropriate.

## 📖 Task Explanations

When you have an `@Observable` model and need two-way bindings into its properties (for text fields, toggles, and the like), `@Bindable` provides them. It complements `@State`: use `@State` when the view owns and creates the model, and `@Bindable` when the view receives an already-existing observable model and needs to bind to it. This pairing lets forms and editors mutate a shared model directly and cleanly, without the boilerplate of manual getters and setters, and it composes naturally as you pass models through the view hierarchy.

## 💡 What You'll Gain

You will create two-way bindings into observable models with `@Bindable`, enabling clean, direct editing of shared state in forms and detail screens.

## 📚 Dictionary for Developers

*   **`@Bindable`:** A wrapper exposing bindings to an `@Observable` model's properties.
*   **Two-Way Binding:** A connection letting a control both read and write a value.
*   **Model Ownership:** Which view is responsible for creating and holding a model.
*   **Editor View:** A view that mutates a shared model through bindings.
