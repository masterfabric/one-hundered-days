# Day 38: Lists & Navigation - TabView & Split Views

## 📝 Today's Tasks

1.  **Build a `TabView`:** Create tabs with the modern `Tab` API and SF Symbol labels.
2.  **Adopt the Prominent Tab Role:** Use the `.prominent` tab role for a trailing-separated tab (requires iOS 26+).
3.  **Use `NavigationSplitView`:** Build a sidebar/detail layout for iPad.
4.  **Combine Tabs with Stacks:** Give each tab its own `NavigationStack`.

## 📖 Task Explanations

Build a `TabView` with the modern `Tab` API: each tab takes a title, a system image, and its content. Tabs are for genuinely parallel top-level sections a user switches between at will — if one section depends on finishing another, it belongs in a flow, not a tab. Three to five tabs is the practical range before the bar becomes unreadable.

The `.prominent` tab role (iOS 26+) separates a tab to the trailing edge, the way search is presented in Apple's own apps. Use it for exactly that kind of always-available utility tab, and gate it behind an availability check if your deployment target reaches back further.

`NavigationSplitView` is the other top-level container, giving you sidebar, optional middle column, and detail. It adapts on its own: three columns on a wide iPad, collapsing to a stack on a compact iPhone, so a single declaration serves both. Drive it with a selection binding so choosing a sidebar item updates the detail column.

Finally, combine the two properly: put a `NavigationStack` *inside* each tab, never a `TabView` inside a stack. That ordering gives each tab its own independent navigation history, so switching tabs and coming back leaves the user where they were — the behaviour every native app has, and one that's surprisingly easy to break by nesting these containers the other way round.

## 💡 What You'll Gain

By the end of today, you will structure top-level app navigation with tabs and split views, adapting the layout across iPhone and iPad.

## 📚 Dictionary for Developers

*   **`TabView`:** A container presenting mutually exclusive top-level sections.
*   **Prominent Tab Role:** A tab role for a visually separated trailing tab (requires iOS 26+).
*   **`NavigationSplitView`:** A multi-column sidebar/detail navigation container.
*   **Information Architecture:** How an app's content and navigation are organized.
*   **Deployment Target:** The oldest OS version your app supports, gating newer APIs.
