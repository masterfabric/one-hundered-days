# Day 82: Performance & Concurrency in Practice - SwiftUI Rendering Performance

## 📝 Today's Tasks

1.  **Minimize Body Recomputation:** Keep bodies cheap and state minimal and localized.
2.  **Use Stable Identity:** Give `ForEach` stable IDs to avoid needless rebuilds.
3.  **Adopt Lazy State Init:** Use lazy initialization for expensive `@Observable` state (requires iOS 26+).
4.  **Measure View Updates:** Diagnose excessive redraws.

## 📖 Task Explanations

SwiftUI's performance model is simple to state: when state changes, it re-runs the affected `body` properties and diffs the result. So the two levers are how often bodies run and how much work each one does. Keep bodies to layout and cheap reads — no sorting, no date formatting, no decoding — and push that work into the model or a cached property.

Localise state so a change touches the smallest subtree. A `@State` property on a parent invalidates the parent's whole body, so if only one row's checkbox changes, that state belongs to the row. Extracting subviews isn't just organisation: it draws the boundaries that determine what gets recomputed.

Stable identity is the other half. Give `ForEach` a genuine `id` from your model rather than the array index, or every insertion renumbers everything after it and SwiftUI rebuilds rows that didn't change — visible as janky scrolling and lost row state on long lists.

Then adopt lazy state initialisation where setup is expensive (iOS 26+), so an `@Observable` isn't constructed until first use. Finally, measure rather than guess: add a `let _ = Self._printChanges()` at the top of a body to log why it re-ran, or use the SwiftUI instrument to see update counts. That one line usually explains a janky list faster than any amount of reading the code.

## 💡 What You'll Gain

By the end of today, you will keep SwiftUI rendering fast by minimizing recomputation, using stable identity, and adopting lazy state initialization.

## 📚 Dictionary for Developers

*   **Body Recomputation:** SwiftUI re-evaluating a view's `body` after a change.
*   **Stable Identity:** Consistent IDs letting SwiftUI reuse views across updates.
*   **Lazy State Init:** Deferring expensive `@Observable` setup until first use (requires iOS 26+).
*   **Redraw:** Re-rendering a view in response to state change.
*   **`Self._printChanges()`:** A debug call logging which change caused a body to re-evaluate.
