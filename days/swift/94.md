# Day 94: Platform Integration - Swift/Objective-C & C Interop

## 📝 Today's Tasks

1.  **Call Objective-C from Swift:** Use a bridging header to access Obj-C APIs.
2.  **Expose Swift to Objective-C:** Understand `@objc` and the generated header.
3.  **Wrap a C Library:** Call a C API from Swift via a module map.
4.  **Build for a Non-Apple Platform:** Compile a small Swift module with the Swift SDK for Android (or Linux) and run it.

## 📖 Task Explanations

Add an Objective-C file to a Swift project and Xcode offers to create a bridging header; anything you import there is visible to Swift automatically, with Obj-C types mapped to their Swift equivalents. This is how you use an older SDK, a C-based framework wrapper, or code your team wrote a decade ago without rewriting it.

The other direction needs `@objc`. Marking a Swift class (which must inherit from `NSObject`) or its members `@objc` exposes them through the compiler-generated `-Swift.h` header. Note the limits: Swift-only features — generics, enums with associated values, structs, protocols with associated types — can't cross this boundary, which is why the bridge often needs a small adapter type rather than direct exposure.

C libraries come in through a module map, a small file declaring the headers and the library so Swift can `import` it as a module. Swift's C interop is direct — pointers, structs, and functions map across — so the work is usually wrapping that raw surface in a safe Swift API rather than getting the call to work at all.

Finally, build for a non-Apple platform. Swift ships an official SDK for Android and has long run on Linux, so cross-compiling a small module is a matter of installing the SDK and pointing the compiler at it. It's a useful reminder that these interop skills increasingly reach beyond Apple platforms, and that shared business logic in Swift is now a realistic option.

## 💡 What You'll Gain

By the end of today, you will bridge Swift with Objective-C and C, integrating legacy and native libraries, and understand Swift's expanding cross-platform reach.

## 📚 Dictionary for Developers

*   **Bridging Header:** A header exposing Objective-C declarations to Swift.
*   **`@objc`:** An attribute exposing Swift APIs to the Objective-C runtime.
*   **Module Map:** A file exposing a C library as a Swift-importable module.
*   **Interoperability:** The ability of Swift to work with other languages.
*   **Swift SDK for Android:** A cross-compilation toolchain for building Swift for Android.
*   **Generated Header:** The `-Swift.h` file exposing `@objc` Swift declarations to Objective-C.
