# Day 94: Platform Integration - Swift/Objective-C & C Interop

## 📝 Today's Tasks

1.  **Call Objective-C from Swift:** Use a bridging header to access Obj-C APIs.
2.  **Expose Swift to Objective-C:** Understand `@objc` and the generated header.
3.  **Wrap a C Library:** Call a C API from Swift via a module map.
4.  **Adopt the Android SDK Concept:** Note Swift's growing cross-platform reach (Swift SDK for Android).

## 📖 Task Explanations

Native development sometimes means bridging to other languages. Swift interoperates cleanly with Objective-C — a bridging header exposes Obj-C to Swift, and `@objc` plus the generated header exposes Swift back — which matters when integrating older code or certain frameworks. Swift can also call C libraries via module maps, useful for cross-platform or systems code. Beyond Apple platforms, Swift in 2026 is visibly cross-platform, including an official Swift SDK for Android, signaling that these interop skills increasingly reach outside the Apple ecosystem. Knowing how to bridge lets you use the best tool for a job without leaving Swift.

## 💡 What You'll Gain

You will bridge Swift with Objective-C and C, integrating legacy and native libraries, and understand Swift's expanding cross-platform reach.

## 📚 Dictionary for Developers

*   **Bridging Header:** A header exposing Objective-C declarations to Swift.
*   **`@objc`:** An attribute exposing Swift APIs to the Objective-C runtime.
*   **Module Map:** A file exposing a C library as a Swift-importable module.
*   **Interoperability:** The ability of Swift to work with other languages.
