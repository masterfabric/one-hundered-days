# Day 71: Testing with Swift Testing - Fundamentals

## 📝 Today's Tasks

1.  **Write a `@Test`:** Create a test function with the `@Test` macro (Swift Testing).
2.  **Assert with `#expect`:** Verify conditions with `#expect(...)`.
3.  **Require with `#require`:** Halt a test on a precondition using `try #require`.
4.  **Run Both Frameworks:** Keep one XCTest case alongside your Swift Testing tests and run the whole suite.

## 📖 Task Explanations

Write your first test: an ordinary function marked `@Test`, in a file inside your test target. There's no `XCTestCase` subclass to inherit from and no `test` prefix to remember, and you can give it a display name — `@Test("Empty cart totals zero")` — which is what appears in the results.

Assert with `#expect(total == 0)`. Because it's a macro, it captures the expression's structure, so a failure reports the actual values of both sides rather than just "expectation failed". Write a deliberately failing assertion once and read the output — that diagnostic quality is the main practical reason to prefer this over `XCTAssert`.

Use `try #require` when continuing would be pointless: unwrapping an optional you're about to use, or checking a precondition the rest of the test depends on. `#expect` records a failure and carries on; `#require` throws and ends the test there, which stops one broken assumption from producing a cascade of confusing failures.

Finally, keep an XCTest case in the same target and run everything together. They coexist, which means migration is incremental rather than a rewrite — new tests in Swift Testing, old ones converted when you happen to touch them. Note that UI tests still use XCTest, so this interop isn't a transitional state you'll fully leave behind.

## 💡 What You'll Gain

By the end of today, you will write your first tests with the modern Swift Testing framework, using `#expect` and `#require` for clear, expressive checks.

## 📚 Dictionary for Developers

*   **Swift Testing:** Apple's modern test framework using macros.
*   **`@Test`:** A macro marking a function as a test.
*   **`#expect`:** A macro asserting a condition with rich failure output.
*   **`#require`:** A macro that stops the test if a condition/unwrap fails.
*   **Test Trait:** Metadata such as `.disabled` or `.timeLimit` attached to a test or suite.
*   **Parallel Execution:** Swift Testing's default of running tests concurrently.
