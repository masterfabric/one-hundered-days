# Day 47: Networking (I) - Codable & Decoding

## 📝 Today's Tasks

1.  **Model the JSON:** Create `Codable` structs matching the API's shape.
2.  **Decode a Response:** Use `JSONDecoder().decode(_:from:)`.
3.  **Map Keys & Dates:** Set `keyDecodingStrategy` and `dateDecodingStrategy`.
4.  **Customize with CodingKeys:** Rename or nest fields via `CodingKeys`.

## 📖 Task Explanations

Model the JSON first. Write structs whose properties mirror the response and conform them to `Codable`, and prefer non-optional properties for fields the API always sends — an optional you added "just in case" hides a contract you never verified. Nested JSON objects become nested structs, and arrays become arrays; the shape of your types *is* the parser.

Then decode: `try JSONDecoder().decode(Feed.self, from: data)`. When it fails, read the error rather than guessing — `DecodingError` tells you the exact coding path and whether the problem was a missing key, a type mismatch, or malformed data. That message will save you far more time than adding optionals until the error goes away.

Configure the decoder for common mismatches instead of writing glue. `keyDecodingStrategy = .convertFromSnakeCase` maps `created_at` to `createdAt` across the whole model; `dateDecodingStrategy = .iso8601` parses standard timestamps into `Date`. Set these once on a shared decoder in your networking layer rather than at each call site.

`CodingKeys` handles what the strategies can't. Declare the enum inside your type to rename a single field, exclude a computed property, or reach a key whose name is unhelpful. For deeper restructuring you can implement `init(from:)` manually and pull values out of nested containers — worth doing once so the generated code stops being magic. Getting decoding right, including how you treat optional and missing fields, is where most networking bugs are won or lost.

## 💡 What You'll Gain

By the end of today, you will decode JSON into type-safe models with `Codable`, using strategies and `CodingKeys` to bridge any API shape cleanly.

## 📚 Dictionary for Developers

*   **`Codable`:** A protocol enabling automatic encoding/decoding of a type.
*   **`JSONDecoder`:** The object that decodes JSON data into `Decodable` values.
*   **Decoding Strategy:** Configuration for key naming, dates, and data formats.
*   **`CodingKeys`:** An enum customizing the mapping between properties and JSON keys.
*   **`DecodingError`:** The detailed error describing which key or type failed to decode.
