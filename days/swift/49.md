# Day 49: Networking (I) - AsyncImage & Remote Media

## 📝 Today's Tasks

1.  **Load Remote Images:** Display network images with `AsyncImage`.
2.  **Show Placeholders:** Provide loading and error phases.
3.  **Leverage HTTP Caching:** Rely on `AsyncImage`'s default HTTP cache support (requires iOS 26+).
4.  **Size & Clip Images:** Use `.resizable`, `.scaledToFill`, and `.clipShape`.

## 📖 Task Explanations

`AsyncImage` loads and displays remote images declaratively, handling the async fetch, a placeholder while loading, and an error state — all without manual `URLSession` code. As of iOS 26, `AsyncImage` respects standard HTTP caching by default, honoring server cache headers so repeat loads are fast and network-friendly with no extra code. Combined with `.resizable`, content-mode modifiers, and `.clipShape`, it covers the vast majority of image needs. For advanced caching or transformations you might later add a library, but the built-in view is the right starting point.

## 💡 What You'll Gain

You will display remote images with proper loading/error states and automatic HTTP caching using the built-in `AsyncImage`.

## 📚 Dictionary for Developers

*   **`AsyncImage`:** A view that asynchronously loads and displays a remote image.
*   **Placeholder:** Content shown while an image is loading.
*   **HTTP Caching:** Reusing responses per server cache headers to avoid refetching.
*   **Content Mode:** How an image scales to fit or fill its frame.
