# Day 43: User Input & Forms - Form & Focus

## 📝 Today's Tasks

1.  **Structure a `Form`:** Group inputs into a `Form` with `Section`s and headers.
2.  **Manage Focus:** Drive keyboard focus with `@FocusState`.
3.  **Move Between Fields:** Advance focus on submit to the next field.
4.  **Dismiss the Keyboard:** Resign focus to dismiss the keyboard.

## 📖 Task Explanations

`Form` gives grouped, platform-styled input screens (think Settings) with almost no effort — just wrap controls in sections. The key to a polished form is focus management: `@FocusState` tracks and controls which field is active, letting you move focus to the next field on submit, jump to the first invalid field, or dismiss the keyboard programmatically. Well-managed focus is one of those invisible details that makes an app feel professional; users notice immediately when a form fights them instead of guiding them through it.

## 💡 What You'll Gain

You will build grouped forms with programmatic focus control, delivering the smooth field-to-field flow users expect.

## 📚 Dictionary for Developers

*   **`Form`:** A container presenting grouped, styled input sections.
*   **`@FocusState`:** A wrapper tracking and controlling which field has keyboard focus.
*   **Focus Management:** Directing keyboard focus between fields programmatically.
*   **`Section`:** A grouped subset of form rows with an optional header/footer.
