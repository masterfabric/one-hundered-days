# Day 43: User Input & Forms - Form & Focus

## 📝 Today's Tasks

1.  **Structure a `Form`:** Group inputs into a `Form` with `Section`s and headers.
2.  **Manage Focus:** Drive keyboard focus with `@FocusState`.
3.  **Move Between Fields:** Advance focus on submit to the next field.
4.  **Dismiss the Keyboard:** Resign focus to dismiss the keyboard.

## 📖 Task Explanations

Wrap your controls in a `Form` and they immediately take on the platform's grouped-settings appearance — the look of the Settings app — with correct insets, separators, and row styling. Break the fields into `Section`s with headers and footers so related inputs sit together; footers are a good place for the short explanatory line that would otherwise clutter the row itself.

Focus is controlled with `@FocusState`. Declare an enum of your fields, add `@FocusState private var focused: Field?`, and attach `.focused($focused, equals: .email)` to each control. Now the property both reports which field is active and moves focus when you assign to it, which is the whole API — reading and writing the same value.

That makes field-to-field movement straightforward: in `.onSubmit`, set `focused = .password` to advance. Pair it with `.submitLabel(.next)` on every field but the last, and `.submitLabel(.done)` on the final one, so the keyboard's return key matches what will actually happen. The same mechanism lets you jump straight to the first invalid field after a failed submit, which you'll use tomorrow.

Dismissing the keyboard is the mirror image: assign `focused = nil`. Hook that to a "Done" button in a `.toolbar(placement: .keyboard)` or to a tap on the background. Well-managed focus is one of those invisible details that makes an app feel professional — users rarely notice it working, but they notice immediately when a form fights them instead of guiding them through it.

## 📚 Dictionary for Developers

*   **`Form`:** A container presenting grouped, styled input sections.
*   **`@FocusState`:** A wrapper tracking and controlling which field has keyboard focus.
*   **Focus Management:** Directing keyboard focus between fields programmatically.
*   **`Section`:** A grouped subset of form rows with an optional header/footer.
*   **`.focused`:** The modifier binding a control to a focus state value.
*   **Keyboard Toolbar:** A toolbar placement that appears above the on-screen keyboard.
