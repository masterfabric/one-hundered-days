# Day 58: Persistence with SwiftData - Relationships

## 📝 Today's Tasks

1.  **Model a Relationship:** Link models with a `@Relationship` (one-to-many).
2.  **Set Delete Rules:** Choose cascade vs nullify delete behavior.
3.  **Traverse Related Data:** Read and mutate related objects through the graph.
4.  **Avoid Retain Issues:** Understand inverse relationships and back-references.

## 📖 Task Explanations

Most data is connected: a list has items, an author has posts. SwiftData models relationships with the `@Relationship` macro, supporting one-to-one, one-to-many, and many-to-many links, with configurable delete rules (cascade deletes children; nullify just breaks the link). Defining inverse relationships keeps both sides of a link consistent automatically. Traversing the object graph — reading a parent's children or a child's parent — works like ordinary property access. Modeling relationships correctly, especially delete rules, prevents orphaned data and subtle bugs as your schema grows.

## 💡 What You'll Gain

You will model connected data with SwiftData relationships and delete rules, building a correct, consistent object graph.

## 📚 Dictionary for Developers

*   **Relationship:** A modeled link between two persistent types.
*   **Delete Rule:** Behavior (cascade/nullify) applied to related objects on delete.
*   **Inverse Relationship:** The back-reference keeping both sides of a link in sync.
*   **Object Graph:** The connected network of related model instances.
