# Day 55: Networking (II) & Architecture - Modularization & Clean Layers

## 📝 Today's Tasks

1.  **Split into SPM Packages:** Move features/utilities into Swift Package Manager modules.
2.  **Define Layer Boundaries:** Separate presentation, domain, and data layers.
3.  **Control Access:** Use access modifiers to enforce module boundaries.
4.  **Manage Cross-Module Dependencies:** Keep dependencies pointing inward toward the domain.

## 📖 Task Explanations

Start by extracting something with no dependencies — a formatting utility, your domain models, a networking package — into a local Swift package. Add it to the workspace, declare it in the app target, and note that the package now builds and tests on its own, which is the first real speed benefit: touching a view no longer recompiles your models.

Then draw the layers. The domain layer holds business rules and knows nothing about the network or SwiftUI; the data layer implements repositories against APIs and databases; the presentation layer holds views and view models. Give each its own module and the boundaries become physical rather than aspirational.

Access control makes them enforceable. Inside a package, `internal` (the default) is invisible to everyone else, so only what you deliberately mark `public` becomes API. That inversion is the point — in a single target everything can reach everything, and the structure survives only as long as everyone's discipline does.

Finally, keep dependencies pointing inward. Presentation and data may depend on domain; domain depends on neither. That's what lets you test business rules with no network, no database, and no UI, and it's what stops a change to an API response rippling into your core logic. When a dependency wants to point outward, the answer is usually a protocol declared in the domain and implemented further out — the same inversion you applied to repositories, now at module scale.

## 💡 What You'll Gain

By the end of today, you will organize an app into layered SPM modules with enforced boundaries, the architecture that keeps large codebases maintainable.

## 📚 Dictionary for Developers

*   **SPM:** Swift Package Manager, for building modular Swift packages.
*   **Layered Architecture:** Separating presentation, domain, and data with clear rules.
*   **Access Control:** Modifiers (`public`/`internal`/`private`) enforcing boundaries.
*   **Dependency Direction:** The rule that dependencies point toward the domain core.
*   **Dependency Inversion:** Declaring a protocol in the inner layer and implementing it in an outer one.
