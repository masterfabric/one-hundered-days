# Day 2: Swift Fundamentals - Value vs. Reference Types

## 📝 Today's Tasks

1.  **Define a `struct`:** Create a `struct Point { var x: Int; var y: Int }` and copy it into a second variable.
2.  **Prove Copy Semantics:** Assign a struct to a second variable, mutate the copy, and print both to confirm the original is unchanged.
3.  **Define a `class`:** Create a `class Counter` and assign it to two variables; mutate through one and observe both change.
4.  **Reason About Identity:** Use `===` to compare class references and understand shared identity.

## 📖 Task Explanations

Begin by defining `struct Point { var x: Int; var y: Int }` and creating an instance. Structs are the default building block in Swift, and the free memberwise initializer means you can write `Point(x: 1, y: 2)` without declaring an `init` at all. Assign that instance to a second variable — this is the setup for everything else today.

Now mutate the copy and print both. The original is untouched, because assigning a value type produces an independent copy rather than a shared reference. (Under the hood Swift uses copy-on-write, so the copy is only made when you actually mutate — you get the semantics without the cost.) This one experiment is worth doing by hand rather than taking on trust.

Then run the mirror experiment with a `class Counter`. Assign one instance to two variables, increment through the first, and read the second: it changed too. Classes are reference types, so both variables point at the same instance in memory. This is the "spooky action at a distance" that makes shared mutable state hard to reason about.

Finally, use `===` to test whether two references point to the same instance, and notice it doesn't compile for structs — identity is a concept that only applies to reference types. Swift and SwiftUI are value-type-first for exactly this reason: you reach for a class only when you genuinely need shared identity, an object lifetime, or reference semantics.

## 💡 What You'll Gain

By the end of today, you will understand the deepest behavioral difference in Swift and know when a copy is made versus when state is shared — the root cause of countless bugs in other languages.

## 📚 Dictionary for Developers

*   **Value Type:** A type copied on assignment; each variable owns an independent instance (`struct`, `enum`).
*   **Reference Type:** A type shared by reference; variables can point to the same instance (`class`).
*   **Copy Semantics:** The behavior where assigning a value type produces an independent copy.
*   **Identity (`===`):** An operator that tests whether two class references point to the same instance.
*   **Copy-on-Write:** An optimization that delays copying a value type until it is actually mutated.
