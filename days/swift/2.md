# Day 2: Swift Fundamentals - Value vs. Reference Types

## 📝 Today's Tasks

1.  **Define a `struct`:** Create a `struct Point { var x: Int; var y: Int }` and copy it into a second variable.
2.  **Observe Copy Semantics:** Mutate the copy and confirm the original is unchanged — structs are value types.
3.  **Define a `class`:** Create a `class Counter` and assign it to two variables; mutate through one and observe both change.
4.  **Reason About Identity:** Use `===` to compare class references and understand shared identity.

## 📖 Task Explanations

Swift's single most important distinction is value vs reference semantics. A `struct` (and `enum`) is a value type: assigning or passing it makes an independent copy, so mutations never leak. A `class` is a reference type: multiple variables can point to the same instance, so a change through one is visible through all. Value types make code easier to reason about because there is no spooky action at a distance, which is exactly why Swift and SwiftUI are value-type-first. You reach for a class only when you genuinely need shared, mutable identity or reference semantics.

## 💡 What You'll Gain

You will understand the deepest behavioral difference in Swift and know when a copy is made versus when state is shared — the root cause of countless bugs in other languages.

## 📚 Dictionary for Developers

*   **Value Type:** A type copied on assignment; each variable owns an independent instance (`struct`, `enum`).
*   **Reference Type:** A type shared by reference; variables can point to the same instance (`class`).
*   **Copy Semantics:** The behavior where assigning a value type produces an independent copy.
*   **Identity (`===`):** An operator that tests whether two class references point to the same instance.
