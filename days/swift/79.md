# Day 79: UI Testing & Accessibility - Preview-Driven Verification

## 📝 Today's Tasks

1.  **Preview Multiple States:** Add previews for loading, empty, error, and populated states.
2.  **Preview Accessibility:** Preview at large Dynamic Type and in dark mode.
3.  **Use Preview Data:** Feed views deterministic sample data.
4.  **Catch Regressions Early:** Scan previews as a fast visual check before building.

## 📖 Task Explanations

Xcode's previews are a powerful, underused testing tool. By adding a preview for each meaningful state of a view — loading, empty, error, and fully populated — you create a visual test matrix you can scan in seconds, catching layout breaks long before they reach the Simulator. Previewing in dark mode and at the largest Dynamic Type sizes surfaces accessibility problems immediately. Feeding views deterministic sample data keeps previews stable. This preview-driven habit gives you many of the benefits of snapshot testing with almost no setup, tightening your feedback loop dramatically.

## 💡 What You'll Gain

You will use rich, multi-state previews as a fast visual test matrix, catching layout and accessibility regressions before building.

## 📚 Dictionary for Developers

*   **Preview Matrix:** A set of previews covering a view's meaningful states.
*   **Sample Data:** Deterministic fixture data used to drive previews.
*   **Visual Regression:** An unintended change in a view's appearance.
*   **Feedback Loop:** The cycle time between making a change and seeing its effect.
