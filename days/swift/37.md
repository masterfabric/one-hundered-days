# Day 37: Lists & Navigation - NavigationStack

## 📝 Today's Tasks

1.  **Set Up a `NavigationStack`:** Wrap content in a `NavigationStack` with a title.
2.  **Push with `NavigationLink`:** Navigate to a detail view on tap.
3.  **Use `navigationDestination`:** Map a value type to its destination view.
4.  **Migrate a `NavigationView` Screen:** Replace a `NavigationView`-based screen with `NavigationStack` and run it.

## 📖 Task Explanations

Wrap your root content in a `NavigationStack` and give the content a `.navigationTitle`. Note where the modifier goes: on the *content inside* the stack, not on the stack itself, because it describes what the bar should say for the current screen rather than configuring the container.

Then push with `NavigationLink`. The value-based form — `NavigationLink("Details", value: item)` — is the one to learn: the link carries data, not a destination view. That means the destination isn't constructed until the user actually navigates, which matters when a list of hundreds of rows would otherwise build hundreds of detail views eagerly.

`navigationDestination(for:)` closes the loop by mapping a value type to the view that displays it. Register it once inside the stack and every link carrying that type resolves through it. Because the mapping lives in one place, you can also drive navigation programmatically by appending to a `NavigationPath` — which is exactly how deep links and "return to this screen after login" are implemented later.

Finally, migrate an old screen. Replace `NavigationView` with `NavigationStack`, convert destination-based links to value-based ones, and add the matching `navigationDestination`. `NavigationView` is deprecated and its behaviour on iPad was always ambiguous — it silently became a split view — so this migration usually fixes real bugs as well as removing a deprecation warning.

## 💡 What You'll Gain

By the end of today, you will implement modern, value-driven navigation with `NavigationStack`, the foundation for programmatic routing and deep linking.

## 📚 Dictionary for Developers

*   **`NavigationStack`:** The modern container managing a stack of pushed views.
*   **`NavigationLink`:** A control that pushes a destination, optionally carrying a value.
*   **`navigationDestination`:** A modifier mapping a value type to a destination view.
*   **Deprecated `NavigationView`:** The legacy container replaced by `NavigationStack`.
*   **`NavigationPath`:** A type-erased collection representing the current pushed stack.
*   **Value-Based Navigation:** Driving navigation by data type rather than by view instance.
