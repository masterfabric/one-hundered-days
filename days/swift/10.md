# Day 10: Types & Protocols - Extensions & Protocol Extensions

## 📝 Today's Tasks

1.  **Extend an Existing Type:** Add a computed property or method to `String` or `Int` via `extension`.
2.  **Organize Code with Extensions:** Group a type's protocol conformance into its own extension.
3.  **Add Default Implementations:** Provide behavior in a protocol extension so conformers get it for free.
4.  **Constrain an Extension:** Use `extension Array where Element: Numeric` for conditional behavior.

## 📖 Task Explanations

Start by extending a type you don't own. Add a computed property or method to `String` or `Int` — something like `var isBlank: Bool` — and call it as though it had always been there. Extensions can add methods, computed properties, initializers, and conformances, but never stored properties, because that would change the type's memory layout.

Then use extensions to organise your own code. The common convention is one extension per protocol conformance: the main declaration holds the type's stored properties, and each conformance lives in its own clearly-labelled block below. On a large type this is the difference between a file you can navigate and one you scroll through hoping.

Protocol extensions are where the real power appears. Providing a method body in an `extension` of the protocol itself means every conforming type gets that behaviour automatically, with no code of its own. Conformers can still supply their own implementation to take precedence — though be aware that for members not listed as protocol requirements, dispatch is static, so which implementation runs depends on the type you're calling through.

Finally, constrain an extension so its contents apply only where they make sense: `extension Array where Element: Numeric` can offer a `sum()` that would be meaningless on an array of views. Small protocols, default implementations, and constrained extensions together are the machinery behind protocol-oriented programming, where behaviour is composed rather than inherited.

## 💡 What You'll Gain

By the end of today, you will extend existing types and give protocols default behavior, learning the composition-over-inheritance style that defines modern Swift design.

## 📚 Dictionary for Developers

*   **Extension:** A construct that adds functionality to an existing type.
*   **Protocol Extension:** An extension on a protocol providing default implementations.
*   **Default Implementation:** Behavior conformers inherit unless they override it.
*   **Constrained Extension:** An extension that applies only when generic constraints are met.
*   **Static Dispatch:** Resolving which implementation to call at compile time based on the static type.
