# Day 10: Types & Protocols - Extensions & Protocol Extensions

## 📝 Today's Tasks

1.  **Extend an Existing Type:** Add a computed property or method to `String` or `Int` via `extension`.
2.  **Organize Code with Extensions:** Group a type's protocol conformance into its own extension.
3.  **Add Default Implementations:** Provide behavior in a protocol extension so conformers get it for free.
4.  **Constrain an Extension:** Use `extension Array where Element: Numeric` for conditional behavior.

## 📖 Task Explanations

Extensions let you add functionality to any type — even ones you don't own — without subclassing. A common convention is to place each protocol conformance in its own extension to keep files readable. The real power appears with protocol extensions: by providing default implementations, you give every conforming type shared behavior automatically, and constrained extensions let that behavior apply only where it makes sense (e.g. summing arrays of numbers). This is the mechanism behind protocol-oriented programming, where behavior is composed from small protocols rather than inherited from base classes.

## 💡 What You'll Gain

You will extend existing types and give protocols default behavior, learning the composition-over-inheritance style that defines modern Swift design.

## 📚 Dictionary for Developers

*   **Extension:** A construct that adds functionality to an existing type.
*   **Protocol Extension:** An extension on a protocol providing default implementations.
*   **Default Implementation:** Behavior conformers inherit unless they override it.
*   **Constrained Extension:** An extension that applies only when generic constraints are met.
