# Day 73: Testing with Swift Testing - Parameterized & Organized Tests

## 📝 Today's Tasks

1.  **Parameterize a Test:** Run one test over many inputs with `@Test(arguments:)`.
2.  **Group with Suites:** Organize related tests into a `@Suite`.
3.  **Share Setup:** Use suite initializers/state for common setup.
4.  **Tag & Filter:** Apply tags to select subsets of tests.

## 📖 Task Explanations

Parameterize instead of copy-pasting. `@Test(arguments: [-1, 0, 1, 999])` runs the same body once per input, and each case is reported separately, so a failure tells you exactly which value broke. Pass `zip(inputs, expected)` when each input has a matching expectation, and the whole table of behaviour lives in the test's signature.

Group related tests into a `@Suite`. A suite is just a struct or a class holding test functions, and it gives the results a hierarchy instead of a flat list. Nest suites when a feature has several areas worth separating.

Shared setup goes in the suite's initializer. Swift Testing creates a fresh instance for each test, so anything you build in `init` — a fake repository, a system under test, sample data — is unique per test and can't leak between them. That's a real improvement on the old `setUp` method with mutable class state, and it's why parallel execution is safe by default.

Finally, tag tests and filter on them. Declare tags in an extension on `Tag`, apply them with `@Test(.tags(.fast))`, and run subsets from the test navigator or the command line. A fast subset for every save and the full suite in CI is a common split — and tags are also how you mark the tests that touch the network so they're easy to exclude.

## 💡 What You'll Gain

By the end of today, you will cover many cases with parameterized tests and structure your suite for scale, keeping tests thorough yet maintainable.

## 📚 Dictionary for Developers

*   **Parameterized Test:** One test executed over multiple argument sets.
*   **`@Suite`:** A grouping of related tests with optional shared setup.
*   **Test Tag:** A label for selecting or filtering tests.
*   **Data-Driven Testing:** Deriving test cases from a table of inputs.
*   **`arguments:`:** The `@Test` parameter supplying the input sets of a parameterized test.
