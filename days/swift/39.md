# Day 39: Lists & Navigation - Sheets, Alerts & Dialogs

## 📝 Today's Tasks

1.  **Present a Sheet:** Show a modal with `.sheet(isPresented:)` and item-based binding.
2.  **Size a Sheet:** Use `.presentationDetents` for half/large heights.
3.  **Show Alerts:** Present an `.alert` with actions and a message.
4.  **Use Confirmation Dialogs:** Offer choices with `.confirmationDialog`, including item bindings (requires iOS 26+).

## 📖 Task Explanations

Present a sheet with `.sheet(isPresented: $showingEditor)` first, then switch to the item form: `.sheet(item: $selectedItem) { item in ... }`. The item version is better in almost every case, because the presented view receives its data as a non-optional parameter — no unwrapping an optional that's still populated while the sheet dismisses, which is the source of the classic "sheet shows the previous item" bug.

Then size it. `.presentationDetents([.medium, .large])` lets a sheet sit at half height and be dragged up, turning it into a bottom sheet; add `.presentationDragIndicator(.visible)` so users can see it's draggable, and `.presentationBackground` when you want it translucent. A medium detent is often the difference between a modal that interrupts and one that feels like part of the screen.

Alerts are for messages that require acknowledgement or a decision. `.alert(_:isPresented:actions:message:)` takes buttons in the actions closure, and marking the dangerous one `.destructive` and the safe one `.cancel` lets the system order and style them correctly. Keep the text short and specific — an alert stops everything the user was doing.

Confirmation dialogs present a set of choices, usually from the bottom of the screen, and are the right tool for "what do you want to do with this item?" They support the same item-binding pattern as sheets (requires iOS 26+). Across all three, prefer binding presentation to a value rather than to a `Bool` plus a separate variable: one source of truth means the presentation and its data can never disagree.

## 💡 What You'll Gain

By the end of today, you will present modal content — resizable sheets, alerts, and dialogs — using the consistent item-binding pattern that keeps presentation state correct.

## 📚 Dictionary for Developers

*   **Sheet:** A modally presented view over the current context.
*   **`presentationDetents`:** Modifier setting the allowed heights of a sheet.
*   **Alert:** A modal conveying a message and requiring a choice.
*   **Confirmation Dialog:** A modal offering a set of actions, often from the bottom.
*   **Item-Based Presentation:** Presenting a modal from an optional value rather than a boolean flag.
