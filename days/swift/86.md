# Day 86: Navigation & Deep Linking - Programmatic Navigation

## 📝 Today's Tasks

1.  **Drive a Navigation Path:** Bind a `NavigationStack` to a `path` you control.
2.  **Push & Pop in Code:** Append/remove values to navigate programmatically.
3.  **Pop to Root:** Reset the stack to its root on demand.
4.  **Persist Navigation State:** Save and restore the path across launches.

## 📖 Task Explanations

Bind the stack to state you own: `@State private var path: [Route] = []` and `NavigationStack(path: $path)`. Navigation is now just an array. That reframing is the whole lesson — everything else today is ordinary array manipulation.

Push by appending and pop by removing: `path.append(.detail(item))` navigates forward, `path.removeLast()` goes back. This is what makes flows possible that view-embedded links can't express — "after saving, return two screens back", or "open this item from a notification with the list already beneath it".

Pop to root with `path.removeAll()`. It's the standard behaviour after completing a flow — a checkout finishing, an onboarding sequence ending — and users expect the back stack to be gone rather than lingering behind the confirmation screen.

Finally, persist it. If your route type is `Codable`, the path is data you can encode to disk and restore at launch, putting the user exactly where they left off. Use `NavigationPath` with its `CodableRepresentation` when the stack holds mixed types, or a typed array when it doesn't. Keep routes as small value types — an id rather than a whole model — so a restored path can't resurrect stale data.

Typed `[Route]` arrays are the right default because the compiler checks every destination, but they only work when every screen on the stack shares one enum. The moment you push from independently developed features with their own route types, switch to `NavigationPath` — you lose exhaustiveness and gain composition. Either way, make each route `Hashable` and keep the payload tiny. Treat the empty path as a first-class state (you're on the root), and don't mix `NavigationLink(value:)` with a manual `path.append` of the same value without considering duplicates — a double-push is a real bug in notification handlers. When a deep link arrives (Day 87), replace the path rather than appending onto whatever the user was looking at, unless the product explicitly wants to preserve the back stack. Preview the path as data: print it after each push and pop, then encode and decode a sample stack so restoration isn't only checked by hand. If decode fails, land on root — handle that as empty-path, not a crash.

## 💡 What You'll Gain

By the end of today, you will control navigation as state with a bound path, enabling programmatic push/pop, pop-to-root, and restorable navigation.

## 📚 Dictionary for Developers

*   **Navigation Path:** A bound collection representing the navigation stack.
*   **Programmatic Navigation:** Driving navigation from code by mutating the path.
*   **Pop to Root:** Clearing the stack back to its first screen.
*   **State Restoration:** Saving and restoring UI/navigation state across launches.
*   **Codable Route:** A navigation value encodable to disk so the stack can be restored.
