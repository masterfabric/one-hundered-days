# Day 13: Generics & Error Handling - Typed Throws & Result

## 📝 Today's Tasks

1.  **Adopt Typed Throws:** Declare `func load() throws(NetworkError)` for precise error typing. Requires Swift 6.0 or later; use the latest stable Swift toolchain.
2.  **Use the `Result` Type:** Represent success/failure as a `Result<Success, Failure>` value.
3.  **Convert Between Them:** Bridge `Result` and throwing with `get()` and `Result(catching:)`.
4.  **Propagate Errors:** Rethrow with `try` and let errors bubble up the call stack.

## 📖 Task Explanations

Start with typed throws, added in Swift 6.0. Declaring `func load() throws(NetworkError)` states exactly which error type can come out, so callers can `catch` exhaustively without a catch-all branch and the compiler can avoid boxing the error. Untyped `throws` is still the right default for wide APIs; typed throws pays off in narrow, self-contained modules where the failure set really is closed.

`Result<Success, Failure>` takes the opposite approach: it turns an outcome into an ordinary value with `.success` and `.failure` cases. Because it's just a value, you can store it in a property, put it in an array, pass it through a completion handler, or hold it until you're ready to deal with it — none of which a thrown error lets you do.

Bridging between the two is a two-line affair. `Result(catching: { try load() })` runs throwing code and captures the outcome, and `result.get()` throws the stored error or returns the value. Knowing both directions means you can accept whichever style an API hands you and convert at the boundary rather than letting one style leak through your whole codebase.

Finally, practise propagation. A function that calls throwing code with `try` and doesn't catch must itself be marked `throws`, and the error travels up until something handles it. Design that deliberately: let low-level functions propagate and decide on one layer — usually the view model — where errors stop travelling and become something the user can see.

## 💡 What You'll Gain

By the end of today, you will use typed throws and `Result` to make error handling precise and composable, choosing the right tool for each boundary in your code.

## 📚 Dictionary for Developers

*   **Typed Throws:** Declaring the specific error type a function can throw (`throws(E)`); requires Swift 6.0+.
*   **`Result`:** An enum with `.success`/`.failure` cases representing an operation's outcome.
*   **Propagation:** Letting an error travel up the call stack via `try`.
*   **`Result(catching:)`:** An initializer that runs throwing code and wraps the outcome.
*   **Error Boundary:** The layer that stops propagation and turns an error into user-visible state.
