# Day 16: Swift Concurrency - async/await

## 📝 Today's Tasks

1.  **Call an `async` Function:** Mark a function `async` and call it with `await`.
2.  **Await a Network Call:** Use `try await URLSession.shared.data(from:)` for a real async request.
3.  **Sequence Async Work:** Chain multiple awaits and reason about suspension points.
4.  **Bridge from Sync:** Kick off async work from a synchronous context with a `Task`.

## 📖 Task Explanations

Swift Concurrency replaces callback pyramids and Combine chains with linear, readable `async`/`await`. An `async` function can suspend at an `await` without blocking a thread, letting the system reuse that thread for other work. The code reads top-to-bottom like synchronous code but runs concurrently under the hood. This is the modern, first-class way to do networking, I/O, and any long-running work in Swift, and SwiftUI integrates with it directly (e.g. `.task`). Starting here sets you up for structured concurrency and actors over the next days.

## 💡 What You'll Gain

You will write asynchronous code that reads like synchronous code, replacing callbacks with `async`/`await` — the foundation of all modern Swift concurrency.

## 📚 Dictionary for Developers

*   **`async`:** A marker that a function can suspend and resume later.
*   **`await`:** A suspension point where a function waits for async work.
*   **Suspension Point:** A place where a task can pause without blocking a thread.
*   **`Task`:** A unit of asynchronous work you can start from sync code.
