# Day 15: Generics & Error Handling - Memory & Value Semantics

## 📝 Today's Tasks

1.  **Reason About ARC:** Understand automatic reference counting for class instances.
2.  **Break Retain Cycles:** Use `weak` and `unowned` references in closures and delegates.
3.  **Capture Lists:** Write `[weak self]` in escaping closures to avoid leaks.
4.  **Prefer Value Types:** Refactor shared mutable state toward value types where possible.

## 📖 Task Explanations

Swift manages class memory with Automatic Reference Counting. Each class instance keeps a count of the strong references to it, and when that count reaches zero it is deallocated immediately — no garbage collector, no unpredictable pause. Add a `deinit` that prints and watch objects die exactly when their last reference goes away.

Then create the classic bug on purpose. Have two class instances hold strong references to each other, drop your references to both, and notice neither `deinit` fires: a retain cycle. Break it by making one side `weak` (it becomes `nil` when the target is deallocated, so it must be an optional `var`) or `unowned` (no optionality, but it traps if you access it after the target is gone — use it only when the reference is guaranteed to outlive you).

The same cycle hides in closures, because an escaping closure stored on an object captures `self` strongly by default. Write `[weak self]` in the capture list and then `guard let self else { return }` inside; the closure now holds only a weak reference, and the work simply doesn't run if the owner has gone. This one pattern accounts for most leaks in real iOS code, so make it a reflex in escaping and long-lived closures.

Finally, sidestep the whole category. Value types have no reference counts and therefore no cycles, so refactoring shared mutable state toward structs eliminates the problem rather than managing it. Reserve classes for genuine shared identity — and get comfortable with Xcode's memory graph debugger, which draws these cycles for you when reasoning alone isn't enough.

## 💡 What You'll Gain

By the end of today, you will prevent memory leaks by understanding ARC and capture semantics — a prerequisite for safe closures, async code, and long-lived view models.

## 📚 Dictionary for Developers

*   **ARC:** Automatic Reference Counting, Swift's memory management for class instances.
*   **Retain Cycle:** A situation where objects reference each other and are never freed.
*   **`weak`/`unowned`:** Reference kinds that don't keep an object alive, breaking cycles.
*   **Capture List:** The `[weak self]` syntax controlling how a closure captures references.
*   **Strong Reference:** A reference that keeps its target alive by incrementing the retain count.
*   **Memory Graph Debugger:** An Xcode tool that visualizes live objects and the references between them.
