# Day 15: Generics & Error Handling - Memory & Value Semantics

## 📝 Today's Tasks

1.  **Reason About ARC:** Understand automatic reference counting for class instances.
2.  **Break Retain Cycles:** Use `weak` and `unowned` references in closures and delegates.
3.  **Capture Lists:** Write `[weak self]` in escaping closures to avoid leaks.
4.  **Prefer Value Types:** Refactor shared mutable state toward value types where possible.

## 📖 Task Explanations

Swift manages class memory with Automatic Reference Counting (ARC): an object lives as long as something strongly references it. The classic bug is a retain cycle, where two objects (or a closure and its owner) hold each other strongly and neither is ever freed. You break cycles with `weak` (becomes `nil` when the target is gone) or `unowned` (assumed to outlive the reference) and by writing capture lists like `[weak self]` in escaping closures. Because value types have no such cycles, favoring structs also sidesteps a whole category of leaks. This knowledge is essential before writing async and UI code.

## 💡 What You'll Gain

You will prevent memory leaks by understanding ARC and capture semantics — a prerequisite for safe closures, async code, and long-lived view models.

## 📚 Dictionary for Developers

*   **ARC:** Automatic Reference Counting, Swift's memory management for class instances.
*   **Retain Cycle:** A situation where objects reference each other and are never freed.
*   **`weak`/`unowned`:** Reference kinds that don't keep an object alive, breaking cycles.
*   **Capture List:** The `[weak self]` syntax controlling how a closure captures references.
