# Day 7: Types & Protocols - Classes, Inheritance & Init

## 📝 Today's Tasks

1.  **Define a `class`:** Create a class with initializers and mark it `final` unless subclassing is intended.
2.  **Use Inheritance:** Subclass, `override` a method, and call `super`.
3.  **Manage Initialization:** Distinguish designated vs convenience initializers.
4.  **Add a `deinit`:** Print from `deinit`, then release the last reference and watch when it fires.

## 📖 Task Explanations

Define a class with an initializer and mark it `final`. A final class cannot be subclassed, which lets the compiler devirtualize its method calls and, more importantly, states your intent. Swift's convention is to make classes final by default and open them up only when you have a concrete reason to allow subclassing.

Then remove `final` and subclass it. `override` replaces a superclass method, and calling `super.method()` inside runs the original implementation — usually first for setup, last for teardown. Try overriding a computed property as well as a method, and note that the compiler requires the `override` keyword so an accidental name collision can't silently shadow something.

Initialization in classes is stricter than in structs. A *designated* initializer fully sets up the instance and must initialize every stored property before calling `super.init`; a *convenience* initializer is marked `convenience` and delegates across to a designated one. This two-phase process is what guarantees no method can ever observe a partly-initialized object.

Finally, add a `deinit` that prints, then release the last reference — set the variable to `nil` or let it go out of scope — and watch the message appear. That moment is ARC deallocating your object, and seeing it fire (or fail to) is the most direct way to understand object lifetime before you meet retain cycles on Day 15. Note that structs have no `deinit`, because a value type has no shared lifetime to end.

## 💡 What You'll Gain

By the end of today, you will use classes correctly — with proper initialization and lifetime management — and know why Swift steers you toward value types and protocols instead of deep inheritance.

## 📚 Dictionary for Developers

*   **Inheritance:** A class deriving properties and behavior from a superclass.
*   **`override`:** Replacing a superclass method or property in a subclass.
*   **Designated vs Convenience Init:** The primary initializer vs a secondary one that delegates to it.
*   **`deinit`:** A method that runs when a class instance is deallocated.
*   **`final`:** A modifier preventing a class from being subclassed or a member from being overridden.
