# Day 7: Types & Protocols - Classes, Inheritance & Init

## 📝 Today's Tasks

1.  **Define a `class`:** Create a class with initializers and mark it `final` unless subclassing is intended.
2.  **Use Inheritance:** Subclass, `override` a method, and call `super`.
3.  **Manage Initialization:** Distinguish designated vs convenience initializers.
4.  **Understand Deinitialization:** Add a `deinit` and reason about object lifetime.

## 📖 Task Explanations

Classes bring reference semantics, inheritance, and deinitializers. Inheritance lets a subclass extend or override a superclass, but Swift encourages composition and protocols over deep class hierarchies, so mark classes `final` by default and subclass deliberately. Initialization in classes is stricter than in structs: designated initializers fully set up an instance, convenience initializers delegate to them, and the compiler enforces a two-phase process to guarantee every property is set before use. `deinit` runs when the last reference is released, which matters for cleaning up resources.

## 💡 What You'll Gain

You will use classes correctly — with proper initialization and lifetime management — and know why Swift steers you toward value types and protocols instead of deep inheritance.

## 📚 Dictionary for Developers

*   **Inheritance:** A class deriving properties and behavior from a superclass.
*   **`override`:** Replacing a superclass method or property in a subclass.
*   **Designated vs Convenience Init:** The primary initializer vs a secondary one that delegates to it.
*   **`deinit`:** A method that runs when a class instance is deallocated.
