# Day 52: Networking (II) & Architecture - Repository Pattern

## 📝 Today's Tasks

1.  **Define a Repository Protocol:** Declare the data operations a feature needs.
2.  **Implement with the API Client:** Back the repository with the network client.
3.  **Abstract the Source:** Hide whether data comes from network, cache, or disk.
4.  **Return Domain Models:** Map API DTOs to clean domain types.

## 📖 Task Explanations

Start from what a feature needs, not from what the API offers. A `TaskRepository` protocol declaring `fetchTasks() async throws -> [Task]` and `save(_:)` describes operations in your app's language; the API's pagination, envelopes, and endpoint names stay on the other side of it.

Implement it with the API client. The concrete `RemoteTaskRepository` holds the client, calls the right endpoints, and returns domain models. The feature depends on the protocol and never learns which implementation it got — which is the entire benefit, and the reason to define the protocol before writing the implementation rather than extracting it afterwards.

Then use that freedom to hide the source. The same protocol can be satisfied by a cache-first implementation that returns local data immediately and refreshes in the background, or by one that falls back to disk when offline. Callers don't change, because "where did this come from?" was never part of the contract.

Finally, map DTOs to domain models at this boundary. The DTO mirrors the API's raw shape — snake_case, nullable everything, string dates — while your domain model has non-optional properties, real `Date`s, and enums instead of magic strings. Doing that conversion in the repository means an API change touches one file, and it stops the backend's quirks from spreading into your views.

## 💡 What You'll Gain

By the end of today, you will abstract data access behind repositories, decoupling features from their sources and enabling caching, offline, and testing.

## 📚 Dictionary for Developers

*   **Repository:** An abstraction over data sources exposing domain operations.
*   **DTO:** A Data Transfer Object mirroring an API's raw shape.
*   **Domain Model:** A clean model your app uses, mapped from DTOs.
*   **Abstraction Boundary:** A protocol hiding implementation details behind an interface.
*   **Cache-First:** Returning stored data immediately while refreshing from the network behind it.
