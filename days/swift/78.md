# Day 78: UI Testing & Accessibility - Dynamic Type & Inclusive Design

## 📝 Today's Tasks

1.  **Support Dynamic Type:** Use text styles and test at large accessibility sizes.
2.  **Respect Reduce Motion:** Honor `\.accessibilityReduceMotion` for animations.
3.  **Ensure Contrast:** Check color contrast and support increased contrast.
4.  **Provide Alternatives:** Don't rely on color alone to convey meaning.

## 📖 Task Explanations

Dynamic Type is the highest-impact accessibility setting, because far more people enlarge their text than use VoiceOver. Use the named text styles rather than fixed point sizes and your text scales automatically; then set the preview's Dynamic Type slider to the largest accessibility size and watch which layouts break. Fixed-height rows, side-by-side labels, and text next to icons are where it fails first — `ViewThatFits` and reflowing to a vertical stack are the usual fixes.

Reduce Motion is next. Read `@Environment(\.accessibilityReduceMotion)` and, when it's on, replace large movement with a cross-fade or no animation at all. This isn't a preference about taste: vestibular disorders make big parallax and zoom effects genuinely nauseating.

Then check contrast. Body text needs a 4.5:1 ratio against its background (3:1 for large text) to meet WCAG AA — the Accessibility Inspector in Xcode measures it for you. Also honour `\.colorSchemeContrast` when the user has asked for increased contrast, which usually means dropping the subtle greys.

Finally, never let colour carry meaning alone. A red border marking an invalid field is invisible to a colour-blind user, so add an icon or a message; a green dot for "online" needs a label. The general rule holds across all four of these: every one of these settings is readable from the environment, so honouring them is a habit rather than a project.

## 💡 What You'll Gain

By the end of today, you will support Dynamic Type, Reduce Motion, and contrast needs, building interfaces that work for the widest range of users.

## 📚 Dictionary for Developers

*   **Dynamic Type:** The system feature scaling text to user preference.
*   **Reduce Motion:** An accessibility setting requesting gentler animation.
*   **Color Contrast:** The luminance difference ensuring readable text.
*   **Inclusive Design:** Designing for the full range of user abilities and settings.
*   **WCAG:** The Web Content Accessibility Guidelines, whose contrast ratios apply to apps too.
