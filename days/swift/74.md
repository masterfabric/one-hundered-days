# Day 74: Testing with Swift Testing - Testing Errors & Edge Cases

## 📝 Today's Tasks

1.  **Assert Throwing:** Verify a function throws with `#expect(throws:)`.
2.  **Test Failure Paths:** Cover error and empty states, not just success.
3.  **Check Boundaries:** Test min/max, empty, and nil inputs.
4.  **Confirm Async Events:** Use confirmations to test callbacks/streams.

## 📖 Task Explanations

Assert failures explicitly. `#expect(throws: NetworkError.timeout) { try client.send(request) }` verifies both that the call throws and that it throws the *right* error — a test asserting only that something threw will happily pass when it throws for a completely different reason.

Then cover the paths nobody enjoys writing. Network failure, a 401, an empty result set, a malformed response. This is where bugs actually live: the happy path gets exercised constantly during development, while the error branch may not run until a user is on a train with no signal. A suite that only tests success provides false comfort.

Boundaries are the other reliable source of bugs. Test the empty collection, the single element, the maximum, the minimum, zero, negative numbers, and `nil` wherever the type allows it. Off-by-one errors and unhandled empties cluster at exactly these values, and a parameterized test from yesterday covers the whole set in one function.

Finally, use confirmations for async events: `await confirmation { confirm in ... }` asserts that a callback, delegate method, or stream emission happened, and how many times. `expectedCount: 0` is the version people forget — it proves something *didn't* fire, which is how you test that a cancelled request doesn't deliver a result.

## 💡 What You'll Gain

By the end of today, you will test error paths, boundaries, and async events deliberately, turning your suite into a genuine safety net.

## 📚 Dictionary for Developers

*   **`#expect(throws:)`:** An assertion that code throws an expected error.
*   **Edge Case:** An input at the boundary of valid behavior.
*   **Failure Path:** A code path handling errors or empty results.
*   **Confirmation:** A Swift Testing tool asserting async events occur as expected.
*   **`Issue.record`:** An API reporting a failure without a boolean expectation.
