# Day 74: Testing with Swift Testing - Testing Errors & Edge Cases

## 📝 Today's Tasks

1.  **Assert Throwing:** Verify a function throws with `#expect(throws:)`.
2.  **Test Failure Paths:** Cover error and empty states, not just success.
3.  **Check Boundaries:** Test min/max, empty, and nil inputs.
4.  **Confirm Async Events:** Use confirmations to test callbacks/streams.

## 📖 Task Explanations

Robust code is proven by its failure tests. Swift Testing verifies that a function throws the expected error with `#expect(throws:)`, and disciplined testing means covering the unglamorous paths — network failures, empty results, boundary values, and nil inputs — where bugs actually live. For asynchronous events (a stream emitting, a callback firing), confirmations assert that something happened the expected number of times. Testing edge cases and errors deliberately is what turns a suite from a false-comfort into a genuine safety net that catches regressions before users do.

## 💡 What You'll Gain

You will test error paths, boundaries, and async events deliberately, turning your suite into a genuine safety net.

## 📚 Dictionary for Developers

*   **`#expect(throws:)`:** An assertion that code throws an expected error.
*   **Edge Case:** An input at the boundary of valid behavior.
*   **Failure Path:** A code path handling errors or empty results.
*   **Confirmation:** A Swift Testing tool asserting async events occur as expected.
