# Day 62: Advanced SwiftUI UI - ViewBuilder & Custom Containers

## 📝 Today's Tasks

1.  **Use `@ViewBuilder`:** Write a function or property that builds views conditionally.
2.  **Accept Content Closures:** Build a container that takes `@ViewBuilder content`.
3.  **Compose Flexible APIs:** Design a reusable container like a styled card wrapper.
4.  **Write a Tiny Result Builder:** Implement a minimal `@resultBuilder` of your own to see what `@ViewBuilder` does.

## 📖 Task Explanations

Start by marking a helper `@ViewBuilder`. Without it, a function returning views can't contain an `if` or a `switch`, because each branch produces a different type; with it, the compiler assembles those branches into a single opaque view for you. Try writing one both ways to see exactly which error the attribute removes.

Then build a container that accepts children. Declare `let content: Content` with `Content: View` and take `@ViewBuilder content: () -> Content` in the initializer, storing `content()`. Your container now takes a trailing closure exactly like `VStack` does — because that is precisely how `VStack` is written.

Use that to wrap arbitrary content in shared behaviour: a card with consistent padding and background, a section with a styled header, a loading overlay that dims whatever it contains. The caller supplies the inside, you supply the frame around it. This is the pattern behind almost every reusable component worth extracting.

Finally, write a minimal `@resultBuilder` yourself — one that collects `String`s, say, with `buildBlock` and `buildOptional`. Ten lines is enough to see that `@ViewBuilder` is not compiler magic but an ordinary Swift feature: each statement in the block becomes an argument to `buildBlock`, and `if`/`else` map to `buildOptional` and `buildEither`. Once that clicks, SwiftUI's syntax stops feeling special and starts feeling like a library.

## 💡 What You'll Gain

By the end of today, you will build custom, composable containers using `@ViewBuilder`, writing components as flexible as SwiftUI's own.

## 📚 Dictionary for Developers

*   **`@ViewBuilder`:** A result builder assembling multiple views into one.
*   **Result Builder:** A Swift feature transforming a block into a built value.
*   **Content Closure:** A `@ViewBuilder` parameter supplying a container's children.
*   **Composable Container:** A reusable view wrapping caller-supplied content.
*   **`buildBlock`:** The result-builder method combining the statements of a block into one value.
