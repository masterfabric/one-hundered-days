# Day 63: Advanced SwiftUI UI - PreferenceKey & Layout Communication

## 📝 Today's Tasks

1.  **Define a `PreferenceKey`:** Create a key to pass data up the view tree.
2.  **Report a Value:** Emit a child's size/position via `.preference`.
3.  **Read It in an Ancestor:** Consume it with `.onPreferenceChange`.
4.  **Build a Real Use Case:** Measure content to drive a parent's layout.

## 📖 Task Explanations

Define a `PreferenceKey`: a type with a `defaultValue` and a static `reduce` function that merges values from multiple children. `reduce` is the part to think about — if several children report, you decide whether to take the maximum, sum them, or collect them into an array.

Report from a child with `.preference(key:value:)`. The usual pattern pairs it with a background `GeometryReader`, so the child reports its own measured size without the reader affecting the layout: `.background(GeometryReader { proxy in Color.clear.preference(key: SizeKey.self, value: proxy.size) })`.

Read it in an ancestor with `.onPreferenceChange(SizeKey.self) { size in ... }`, storing the result in state. Be careful here: writing state that changes the layout that produced the preference can loop. Keep the reported value independent of what you do with it, and watch for the "modifying state during view update" warning, which is the symptom of getting this wrong.

Finally, build something real with it — a custom tab indicator that measures the selected tab and slides underneath it, or a set of labels that all adopt the widest one's width. This upward channel is the exception to SwiftUI's downward data flow, and it exists precisely for layouts that depend on their own content, which no amount of passing values down can solve.

## 💡 What You'll Gain

By the end of today, you will communicate data up the view tree with `PreferenceKey`, enabling content-aware layouts that ordinary data flow can't express.

## 📚 Dictionary for Developers

*   **`PreferenceKey`:** A mechanism for passing values up the view hierarchy.
*   **`.preference`:** A modifier a child uses to report a preference value.
*   **`.onPreferenceChange`:** A modifier an ancestor uses to read reported values.
*   **Upward Data Flow:** Passing information from child to parent in SwiftUI.
*   **`reduce`:** The `PreferenceKey` function combining values reported by multiple children.
