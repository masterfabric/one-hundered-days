# Day 75: Testing with Swift Testing - Test-Driven Habits & Coverage

## 📝 Today's Tasks

1.  **Try a Red-Green-Refactor Cycle:** Write a failing test, make it pass, then refactor.
2.  **Measure Coverage:** Enable code coverage and read the report critically.
3.  **Avoid Brittle Tests:** Test behavior and outcomes, not implementation details.
4.  **Integrate into the Workflow:** Run tests locally before every commit.

## 📖 Task Explanations

Testing pays off most as a habit, not an afterthought. Test-driven development — write a failing test, make it pass, refactor — keeps your design testable and your coverage honest from the start. Code-coverage reports show what's exercised, but treat them as a guide, not a target: 100% coverage of trivial code is worthless, while a few tests on critical logic are gold. Prefer testing observable behavior over internal details so tests don't shatter on every refactor. Running tests before each commit turns your suite into a continuous guardrail.

## 💡 What You'll Gain

You will adopt test-driven habits and use coverage wisely, making testing a continuous guardrail rather than a chore.

## 📚 Dictionary for Developers

*   **TDD:** Test-Driven Development: writing tests before implementation.
*   **Red-Green-Refactor:** The TDD loop of failing test, passing code, then cleanup.
*   **Code Coverage:** A measure of which code your tests execute.
*   **Brittle Test:** A test that breaks on refactors because it checks internals.
