# Day 75: Testing with Swift Testing - Test-Driven Habits & Coverage

## 📝 Today's Tasks

1.  **Try a Red-Green-Refactor Cycle:** Write a failing test, make it pass, then refactor.
2.  **Measure Coverage:** Enable code coverage and read the report critically.
3.  **Refactor a Brittle Test:** Rewrite one test that asserts internals so it asserts observable behavior instead.
4.  **Integrate into the Workflow:** Run tests locally before every commit.

## 📖 Task Explanations

Run one full red-green-refactor cycle deliberately, even if it feels backwards. Write a test for behaviour that doesn't exist yet and watch it fail — that failure proves the test can fail, which an assertion written after the code never establishes. Then write the simplest thing that passes, then clean it up with the test holding you steady.

Turn on code coverage in the scheme and read the report critically. It shows which lines your tests executed, which is useful for spotting whole files nobody has tested. It does not show whether the assertions were meaningful, so treat it as a map of gaps rather than a score to maximise: 100% coverage of trivial getters is worth less than three good tests on your pricing logic.

Then fix a brittle test. Find one that asserts on internals — a private method being called, an exact call order, a specific intermediate value — and rewrite it to assert the observable outcome instead. The signal is a test that breaks during a refactor when nothing the user sees changed; each one of those trains you to distrust the suite.

Finally, make running tests automatic rather than virtuous. Run them before every commit, and wire them into CI on Day 96 so the machine enforces it. A suite that runs continuously is a guardrail; one you remember to run when you're worried is just documentation.

## 💡 What You'll Gain

By the end of today, you will adopt test-driven habits and use coverage wisely, making testing a continuous guardrail rather than a chore.

## 📚 Dictionary for Developers

*   **TDD:** Test-Driven Development: writing tests before implementation.
*   **Red-Green-Refactor:** The TDD loop of failing test, passing code, then cleanup.
*   **Code Coverage:** A measure of which code your tests execute.
*   **Brittle Test:** A test that breaks on refactors because it checks internals.
*   **Behavioral Assertion:** Asserting an observable outcome rather than an internal call.
