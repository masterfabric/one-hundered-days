# Day 72: Testing with Swift Testing - Testing Logic & View Models

## 📝 Today's Tasks

1.  **Test Pure Functions:** Cover business logic with focused tests.
2.  **Test a View Model:** Verify a view model's state after actions.
3.  **Inject Fakes:** Pass a fake repository conforming to your protocol.
4.  **Assert Async Results:** Test `async` methods with `await` in tests.

## 📖 Task Explanations

Start with pure functions, because they're free to test: same input, same output, no setup. Validation rules, date and currency formatting, sorting and filtering logic, price calculations — each one is a test that runs in microseconds and never flakes. If a piece of logic is hard to test, that's usually a signal it should be extracted into a function like these.

Then test a view model. Construct it, call a method, and assert on its state afterwards — `viewModel.items.count`, `viewModel.state`, `viewModel.errorMessage`. You're testing behaviour through the same surface the view uses, which means the tests keep working when you rearrange the internals.

Injecting fakes is what makes this possible, and it's why you built view models against protocols. Write a `FakeRepository` that returns fixed data, and a second one that throws, then assert the view model reaches `loaded` with the right contents in one case and `failed` in the other. No network, no waiting, no flakiness — and error paths become as easy to test as happy ones.

Finally, mark the test `async` and `await` the method directly; Swift Testing handles it with no expectation dance. If the view model is `@MainActor`, annotate the test the same way so the compiler is satisfied. These tests are fast, deterministic, and catch real regressions, which is exactly why they should be the largest part of your suite.

## 💡 What You'll Gain

By the end of today, you will test business logic and view models in isolation using injected fakes, building the fast, reliable core of your test suite.

## 📚 Dictionary for Developers

*   **Unit Test:** A test of a small, isolated piece of logic.
*   **Fake/Mock:** A stand-in implementation used to isolate the code under test.
*   **System Under Test:** The specific component a test is exercising.
*   **Async Test:** A test that awaits asynchronous code and asserts its result.
*   **Dependency Injection:** Passing collaborators in so a test can substitute a fake.
