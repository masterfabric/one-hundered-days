# Day 72: Testing with Swift Testing - Testing Logic & View Models

## 📝 Today's Tasks

1.  **Test Pure Functions:** Cover business logic with focused tests.
2.  **Test a View Model:** Verify a view model's state after actions.
3.  **Inject Fakes:** Pass a fake repository conforming to your protocol.
4.  **Assert Async Results:** Test `async` methods with `await` in tests.

## 📖 Task Explanations

The highest-value tests target your logic: pure functions and view models, not pixels. Because you built view models to depend on protocols, you can inject a fake repository that returns canned data (or errors) and then assert the view model reaches the right state — loaded content, an error message, an empty state. Swift Testing handles `async` naturally, so you `await` a view model's method and check the outcome. These tests are fast, deterministic, and catch real regressions, which is why they form the backbone of a healthy test suite.

## 💡 What You'll Gain

You will test business logic and view models in isolation using injected fakes, building the fast, reliable core of your test suite.

## 📚 Dictionary for Developers

*   **Unit Test:** A test of a small, isolated piece of logic.
*   **Fake/Mock:** A stand-in implementation used to isolate the code under test.
*   **System Under Test:** The specific component a test is exercising.
*   **Async Test:** A test that awaits asynchronous code and asserts its result.
