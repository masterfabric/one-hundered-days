# Day 57: Persistence with SwiftData - @Query & Fetching

## 📝 Today's Tasks

1.  **Fetch with `@Query`:** Display persisted models in a view using `@Query`.
2.  **Sort & Filter:** Add sort descriptors and `#Predicate` filters.
3.  **Insert & Delete:** Mutate the store via the `ModelContext`.
4.  **Observe Auto-Updates:** Watch the UI update automatically as data changes.

## 📖 Task Explanations

`@Query` is SwiftData's SwiftUI-native way to read data: declare it in a view and the framework fetches matching models and keeps the view in sync as the store changes — no manual refetch. You shape results with sort descriptors and type-safe `#Predicate` filters, and you mutate data by inserting or deleting through the `ModelContext`. Because queries are reactive, a change made anywhere is reflected everywhere instantly. This tight loop between the store and the UI is what makes SwiftData feel like a natural extension of SwiftUI's state model.

## 💡 What You'll Gain

You will fetch, filter, and mutate persisted data with `@Query` and `#Predicate`, getting automatic, reactive UI updates.

## 📚 Dictionary for Developers

*   **`@Query`:** A property wrapper fetching persisted models reactively into a view.
*   **`#Predicate`:** A type-safe filter expression for queries.
*   **Sort Descriptor:** A specification of how fetched results are ordered.
*   **Reactive Fetch:** A query that keeps its results in sync with the store.
