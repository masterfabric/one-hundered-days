# Day 57: Persistence with SwiftData - @Query & Fetching

## 📝 Today's Tasks

1.  **Fetch with `@Query`:** Display persisted models in a view using `@Query`.
2.  **Sort & Filter:** Add sort descriptors and `#Predicate` filters.
3.  **Insert & Delete:** Mutate the store via the `ModelContext`.
4.  **Verify Auto-Updates:** Insert a model at runtime and confirm the `@Query` view refreshes with no manual reload.

## 📖 Task Explanations

Declare `@Query private var todos: [Todo]` in a view and the models appear. There's no fetch call and no refresh: the property wrapper reads from the environment's context and keeps itself in sync as the store changes. It only works inside a view — for fetches elsewhere you use `FetchDescriptor` against a context directly.

Shape the results with the query's arguments. `@Query(sort: \.dueDate)` orders them, and `@Query(filter: #Predicate<Todo> { !$0.isDone })` filters. `#Predicate` is checked at compile time against your model's real properties, unlike the old string-based predicates, so a renamed property becomes an error rather than a runtime surprise. Note that only a subset of Swift is expressible inside one — complex logic belongs on the model or in a computed property.

Mutate through the context: `context.insert(todo)` to add, `context.delete(todo)` to remove, and direct property assignment to change. There's no separate update call, because the model object is live — assigning to `todo.title` is the update.

Finally, verify the loop. Insert a model from a button, or delete one from a swipe action, and watch every `@Query` view reflect it immediately without any refresh code — including views on other screens. This reactivity is the reason SwiftData feels like an extension of SwiftUI's state system rather than a database bolted onto it.

## 💡 What You'll Gain

By the end of today, you will fetch, filter, and mutate persisted data with `@Query` and `#Predicate`, getting automatic, reactive UI updates.

## 📚 Dictionary for Developers

*   **`@Query`:** A property wrapper fetching persisted models reactively into a view.
*   **`#Predicate`:** A type-safe filter expression for queries.
*   **Sort Descriptor:** A specification of how fetched results are ordered.
*   **Reactive Fetch:** A query that keeps its results in sync with the store.
*   **`FetchDescriptor`:** A programmatic fetch specification used outside a view.
