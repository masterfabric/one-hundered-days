# Day 35: State & Data Flow - AppStorage & Scene Phase

## 📝 Today's Tasks

1.  **Persist Preferences:** Store simple settings with `@AppStorage` (UserDefaults-backed).
2.  **React to Scene Phase:** Read `\.scenePhase` with `@Environment`, print every transition from an `onChange` handler, and background the app to trigger them.
3.  **Save on Background:** Persist state when the app moves to the background.
4.  **Combine with State:** Blend persisted preferences with in-memory `@State`.

## 📖 Task Explanations

`@AppStorage("theme") private var theme = "system"` reads and writes `UserDefaults` behind an ordinary property. Assigning to it persists the value and re-renders the views that read it, which makes it the shortest path from a settings toggle to a preference that survives relaunch. Keep it to small, non-sensitive values — a theme, a sort order, a "has seen onboarding" flag — since `UserDefaults` is a plist, not a database, and is readable from a device backup.

Next, observe `@Environment(\.scenePhase)`. It reports `.active`, `.inactive`, and `.background`, and you react with `.onChange(of: scenePhase)`. This is the SwiftUI replacement for the old app-delegate lifecycle callbacks, and it's scene-based, so on iPad each window reports its own phase.

Use that to save at the right moment. When the phase becomes `.background`, flush anything unsaved — draft text, scroll position, an in-progress form. You get a short, uninterrupted window there, so keep the work small and synchronous rather than kicking off a long task the system may suspend mid-flight.

Finally, blend the two kinds of state deliberately. Persisted values belong in `@AppStorage`; transient UI state — which sheet is open, what's typed but not committed — belongs in `@State` and should usually die with the screen. Deciding which is which for each piece of state is the actual design work here, and getting it wrong in either direction produces an app that either forgets too much or remembers things the user expected it to drop.

## 💡 What You'll Gain

By the end of today, you will persist lightweight preferences and respond to app lifecycle transitions, making your app feel stateful and well-behaved across launches.

## 📚 Dictionary for Developers

*   **`@AppStorage`:** A wrapper binding a property to a `UserDefaults` key.
*   **`UserDefaults`:** A store for small key-value preference data.
*   **Scene Phase:** The environment value reporting active/inactive/background state.
*   **App Lifecycle:** The states an app moves through during its run.
*   **Draft State:** In-progress user input held in memory until it is explicitly saved.
