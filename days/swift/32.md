# Day 32: State & Data Flow - The Observation Framework

## 📝 Today's Tasks

1.  **Create an `@Observable` Class:** Mark a model class `@Observable` (Observation framework).
2.  **Read It from a View:** Store it in `@State` and render its properties in `body`.
3.  **Measure Fine-Grained Tracking:** Print inside two subviews, change one property, and check which subview re-runs.
4.  **Migrate an `ObservableObject`:** Convert an existing `ObservableObject`/`@Published` view model to `@Observable`.

## 📖 Task Explanations

Create a class and annotate it `@Observable`. That's the whole setup — no protocol conformance, no `@Published` on each property. The macro rewrites your stored properties so reads and writes are reported to SwiftUI's observation machinery, which you can confirm by expanding the macro in Xcode (right-click the attribute → Expand Macro) if you want to see what it generates.

Store it in `@State` when the view creates and owns it, then read its properties in `body`. It may look odd to put a reference type in `@State`, but that's the current pattern: `@State` keeps the instance alive across view re-creations, and observation handles the change notifications. There is no `@StateObject` in this world.

Now measure the tracking. Put two subviews on screen, each reading a different property, and print inside both bodies. Change one property and only that subview's body re-runs — SwiftUI recorded exactly which properties each view read during its last render and invalidates on that basis. Compare that with `ObservableObject`, where any `@Published` change notified every observing view.

Finally, migrate a real view model. Delete the `ObservableObject` conformance, remove every `@Published`, add `@Observable`, and change `@StateObject`/`@ObservedObject` at the call sites to `@State` or a plain `let`. The result is less code, fewer wrappers, and better performance — which is why `@Observable` is the default for new code and `ObservableObject` is only worth keeping where you still need Combine publishers.

## 💡 What You'll Gain

By the end of today, you will manage shared model state with the modern `@Observable` macro, gaining automatic, fine-grained, high-performance UI updates.

## 📚 Dictionary for Developers

*   **Observation:** Apple's framework for tracking changes to reference-type state.
*   **`@Observable`:** A macro making a class's properties observable by SwiftUI.
*   **Fine-Grained Tracking:** Re-rendering only views that read a changed property.
*   **Legacy `ObservableObject`:** The older Combine-based pattern that `@Observable` replaces.
*   **`@Bindable`:** A wrapper creating two-way bindings to an `@Observable` object's properties.
