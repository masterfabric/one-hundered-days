# Day 56: Persistence with SwiftData - @Model & Container

## 📝 Today's Tasks

1.  **Define a `@Model`:** Annotate a class with `@Model` to make it persistent.
2.  **Set Up the Container:** Configure a `ModelContainer` on the app with `.modelContainer`.
3.  **Access the Context:** Read the `@Environment(\.modelContext)`.
4.  **Map SwiftData to Core Data:** Write down which Core Data concept each of `@Model`, `ModelContainer`, and `ModelContext` replaces.

## 📖 Task Explanations

Annotate a class with `@Model` and it becomes persistent. The macro adds the storage and change-tracking machinery for you, so the type stays an ordinary Swift class with ordinary properties — note that it must be a class, since persisted objects have identity and a lifetime in the store. Give it plain `var` properties and a normal initializer.

Then set up the container. `.modelContainer(for: Todo.self)` on your `WindowGroup` creates the store, applies the schema, and injects everything into the environment in one modifier. For previews and tests, create a container with `isStoredInMemoryOnly: true` so each run starts clean and nothing touches disk — do this early, because a preview that writes to the real store gets confusing fast.

Reach the context with `@Environment(\.modelContext)`. The context is your working set: you `insert` new objects, `delete` old ones, and mutate properties directly. Changes are autosaved by default, so an explicit `try context.save()` is only needed when you want to force the write at a specific moment.

Finally, write down the mapping to Core Data — `@Model` for `NSManagedObject` plus the model editor, `ModelContainer` for `NSPersistentContainer`, `ModelContext` for `NSManagedObjectContext`. The correspondence is deliberate, since SwiftData sits on the same storage engine. Knowing it helps twice: Core Data's documentation still applies to the layer underneath, and you'll be able to read the enormous amount of existing code and writing that predates SwiftData.

## 💡 What You'll Gain

By the end of today, you will set up local persistence with SwiftData's `@Model` and `ModelContainer`, the modern replacement for Core Data.

## 📚 Dictionary for Developers

*   **SwiftData:** Apple's modern persistence framework, successor to Core Data.
*   **`@Model`:** A macro turning a class into a persistent model.
*   **`ModelContainer`:** The object managing the underlying persistent store.
*   **`ModelContext`:** The workspace for inserting, deleting, and saving models.
*   **Persistent Store:** The on-disk database a `ModelContainer` reads from and writes to.
*   **`.modelContainer(for:)`:** The scene modifier that injects a container into the view hierarchy.
