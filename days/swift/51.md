# Day 51: Networking (II) & Architecture - API Client

## 📝 Today's Tasks

1.  **Design an API Client:** Build a reusable client that performs requests and decodes responses.
2.  **Define Endpoints:** Model endpoints (path, method, body) as values.
3.  **Centralize Errors:** Map all failures to a single app error type.
4.  **Inject the Session:** Accept a `URLSession` (or protocol) for testability.

## 📖 Task Explanations

Build one type that owns request execution. It takes an endpoint, builds the `URLRequest`, runs it, checks the status code, decodes the body, and maps errors — the sequence you've been writing by hand for five days, in one place. Everything above it asks for typed data; nothing above it touches `URLSession` again.

Model endpoints as values rather than baking URLs into methods. A small struct or enum carrying path, method, query items, and body keeps the client itself generic — one `send<T: Decodable>(_ endpoint: Endpoint) async throws -> T` function serves your whole API. Adding a new route then means adding a value, not another near-duplicate function.

Centralise error mapping here too. Transport failures, non-2xx responses, and decoding errors all funnel into one `APIError` type, so callers handle a small closed set instead of three unrelated error families. This is also the natural place to attach the auth header and any shared decoder configuration, since everything flows through the same path.

Finally, inject the session rather than reaching for `URLSession.shared` inside. Accept it in the initializer — ideally as a protocol you define with a single `data(for:)` requirement — so a test can pass a fake that returns canned responses instantly with no network at all. This is your first real architectural boundary, and injection is the thing that makes it worth having.

## 💡 What You'll Gain

By the end of today, you will build a reusable, testable API client that centralizes networking behind a clean boundary — your first real architecture layer.

## 📚 Dictionary for Developers

*   **API Client:** A reusable component encapsulating network requests and decoding.
*   **Endpoint:** A value describing a specific API route and its parameters.
*   **Error Mapping:** Translating diverse failures into one app-level error type.
*   **Injection Point:** A dependency (like the session) supplied from outside for testability.
*   **Generic Send Function:** One request method parameterized over the response type it decodes.
