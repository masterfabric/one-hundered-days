# Day 28: Layout & Composition - GeometryReader & Layout Guides

## 📝 Today's Tasks

1.  **Read Available Space:** Use `GeometryReader` to size content to its container.
2.  **Use `containerRelativeFrame`:** Size a view relative to its container without a reader.
3.  **Respect the Safe Area:** Use `.safeAreaInset` and `.ignoresSafeArea` deliberately.
4.  **Implement a Minimal `Layout`:** Write a small custom `Layout` conformance and use it in one screen.

## 📖 Task Explanations

`GeometryReader` gives a view access to the size it has been offered, exposing a proxy with `size`, `safeAreaInsets`, and coordinate-space conversion. Use it when a child genuinely needs proportional sizing — "this bar is 40% of the width". The catch is that it accepts all the space offered to it and doesn't size to its content, so dropping one into a stack often collapses the layout around it; keep it as small and as deep in the tree as possible.

For the common cases you no longer need it. `.containerRelativeFrame(.horizontal) { width, _ in width * 0.9 }` sizes a view against its container directly, with no reader and no layout side effects. Reach for this first and treat `GeometryReader` as the fallback for genuinely custom geometry.

Safe-area handling is next. `.safeAreaInset(edge:)` adds a view (a toolbar, a floating button bar) and shrinks the content's safe area to match, so nothing ends up underneath it. `.ignoresSafeArea()` does the opposite, letting a background extend under the notch and home indicator — apply it to the background layer, not to the content, or your text will slide under the system UI.

Finally, implement a tiny custom `Layout`. Conform a struct to the protocol, implement `sizeThatFits` and `placeSubviews`, and use it once in place of an `HStack`. You almost never need this in practice, but writing one makes SwiftUI's layout contract concrete: the parent proposes a size, each child reports what it wants, and the parent decides where everything goes.

## 💡 What You'll Gain

By the end of today, you will build space-aware, adaptive layouts and place content correctly around device safe areas.

## 📚 Dictionary for Developers

*   **`GeometryReader`:** A container exposing its proposed size and coordinate space.
*   **`containerRelativeFrame`:** A modifier sizing a view relative to its container.
*   **Safe Area:** The region avoiding notches, indicators, and system bars.
*   **`Layout` Protocol:** An API for writing fully custom layout algorithms.
*   **`sizeThatFits`:** The `Layout` method reporting the size a container wants for a proposal.
