# Day 28: Layout & Composition - GeometryReader & Layout Guides

## 📝 Today's Tasks

1.  **Read Available Space:** Use `GeometryReader` to size content to its container.
2.  **Use `containerRelativeFrame`:** Size a view relative to its container without a reader.
3.  **Respect the Safe Area:** Use `.safeAreaInset` and `.ignoresSafeArea` deliberately.
4.  **Understand the Layout Protocol:** Know that a custom `Layout` exists for advanced needs.

## 📖 Task Explanations

Sometimes a view needs to know how much space it has. `GeometryReader` exposes the proposed size and coordinate space of its container, enabling proportional layouts — though it should be used sparingly because it takes all offered space. The newer `containerRelativeFrame` covers many common cases (like "90% of the container") without a reader. Safe-area APIs (`.safeAreaInset`, `.ignoresSafeArea`) let you place content correctly around notches, home indicators, and toolbars. For truly custom arrangements, SwiftUI's `Layout` protocol lets you write your own layout algorithm.

## 💡 What You'll Gain

You will build space-aware, adaptive layouts and place content correctly around device safe areas.

## 📚 Dictionary for Developers

*   **`GeometryReader`:** A container exposing its proposed size and coordinate space.
*   **`containerRelativeFrame`:** A modifier sizing a view relative to its container.
*   **Safe Area:** The region avoiding notches, indicators, and system bars.
*   **`Layout` Protocol:** An API for writing fully custom layout algorithms.
