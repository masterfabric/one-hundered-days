# Day 100: Release & CI/CD - Capstone: Ship a Complete App

## 📝 Today's Tasks

1.  **Integrate Everything:** Combine architecture, persistence, networking, tests, and CI into one app.
2.  **Harden for Production:** Add error handling, accessibility, and empty/error states throughout.
3.  **Prepare the Release:** Complete metadata, run the CI pipeline, and submit to TestFlight.
4.  **Reflect & Plan Next Steps:** Review what you built and choose an area to deepen.

## 📖 Task Explanations

Assemble the whole thing. One app, built the way the last hundred days argued for: a clean MVVM structure with dependencies injected at the composition root, SwiftData for persistence, an async networking layer behind a repository protocol, and a test suite that runs in CI on every push. Scope it honestly — a small app where every layer is done properly teaches more than a large one held together with shortcuts.

Then harden it, which is the part that separates a demo from a product. Every screen gets its loading, empty, and error states with a way to recover; every icon-only button gets an accessibility label; every layout survives the largest Dynamic Type size. Walk the app with VoiceOver, run it on the oldest device you support, and turn the network off mid-request to see what the user actually sees.

Take it through the full release path. Complete the metadata and privacy label, let CI build and sign it, and push a TestFlight build to at least one other person. The pipeline working end to end — commit to installed build with no manual step — is the concrete proof that the CI/CD section landed.

Finally, reflect and choose a direction. Note which parts you reached for confidently and which you looked up every time; the second list is your syllabus. Then pick one area to go deep in — concurrency and performance, architecture at scale, animation and custom rendering, or the platform integration surface. A hundred days buys competence across the whole stack, which is exactly what you need to specialise from.
