# Day 12: Generics & Error Handling - Throwing & Catching

## 📝 Today's Tasks

1.  **Define an Error Type:** Create `enum NetworkError: Error { case badURL, timeout }`.
2.  **Write a Throwing Function:** Mark a function `throws` and `throw` on failure.
3.  **Handle with `do`/`catch`:** Call it inside `do`/`catch` and pattern-match the error.
4.  **Use `try?` and `try!`:** Convert throws to an optional or assert non-failure appropriately.

## 📖 Task Explanations

Define your error type first: `enum NetworkError: Error { case badURL, timeout }`. Any type can conform to `Error`, but an enum is usually right, because the set of ways an operation can fail is finite and each case can carry its own payload if it needs to.

Then mark a function `throws` and `throw` from it on failure. The keyword is part of the function's type, so the compiler forces every caller to write `try` and deal with the possibility — errors cannot be silently ignored the way an unchecked return code can. A throwing function returns its value normally on the happy path; failure takes a separate exit.

Handle it in `do`/`catch`. Inside `do`, prefix the call with `try`; in the `catch` blocks, pattern-match specific cases (`catch NetworkError.timeout`) before the general one, and remember that a final untyped `catch` binds the error to an implicit `error` constant. Matching on cases rather than inspecting a description string is what makes error handling reliable.

Finally, use the two shortcuts appropriately. `try?` converts a throwing call into an optional, discarding *why* it failed — fine when any failure means the same fallback. `try!` asserts failure is impossible and traps if it isn't, so reserve it for genuinely unreachable cases such as a hard-coded regex you know compiles. Unlike exceptions in other languages, none of this unwinds silently: errors here are ordinary values travelling a declared path.

## 💡 What You'll Gain

By the end of today, you will surface and handle failures explicitly with Swift's error model, writing code where the compiler ensures no failure path is silently ignored.

## 📚 Dictionary for Developers

*   **`Error`:** The protocol all error types conform to.
*   **`throws`:** A marker that a function can fail by throwing an error.
*   **`do`/`catch`:** The construct for running throwing code and handling its errors.
*   **`try?`:** An operator that converts a throwing call's result into an optional.
*   **`rethrows`:** A marker for a function that only throws if the closure passed to it throws.
