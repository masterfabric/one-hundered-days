# Day 12: Generics & Error Handling - Throwing & Catching

## 📝 Today's Tasks

1.  **Define an Error Type:** Create `enum NetworkError: Error { case badURL, timeout }`.
2.  **Write a Throwing Function:** Mark a function `throws` and `throw` on failure.
3.  **Handle with `do`/`catch`:** Call it inside `do`/`catch` and pattern-match the error.
4.  **Use `try?` and `try!`:** Convert throws to an optional or assert non-failure appropriately.

## 📖 Task Explanations

Swift models recoverable failures with typed error values, not exceptions that unwind silently. A function that can fail is marked `throws`, callers must acknowledge it with `try`, and errors are handled in `do`/`catch` where you can pattern-match specific cases. `try?` turns a throwing call into an optional when you don't care why it failed, and `try!` asserts it cannot fail. This explicit, value-based approach means the compiler forces you to consider failure paths, producing far more robust code than languages where errors can be ignored.

## 💡 What You'll Gain

You will surface and handle failures explicitly with Swift's error model, writing code where the compiler ensures no failure path is silently ignored.

## 📚 Dictionary for Developers

*   **`Error`:** The protocol all error types conform to.
*   **`throws`:** A marker that a function can fail by throwing an error.
*   **`do`/`catch`:** The construct for running throwing code and handling its errors.
*   **`try?`:** An operator that converts a throwing call's result into an optional.
