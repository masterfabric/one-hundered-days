# Day 89: Navigation & Deep Linking - Coordinators & Routing

## 📝 Today's Tasks

1.  **Centralize Routing:** Introduce a router/coordinator owning the navigation path.
2.  **Decouple Screens:** Let screens request navigation without knowing destinations.
3.  **Model Routes as Values:** Define an enum of routes for the app.
4.  **Test Navigation Logic:** Unit-test routing decisions in isolation.

## 📖 Task Explanations

As navigation grows complex, centralizing it pays off. A router (or coordinator) is an `@Observable` object that owns the navigation path and exposes intent-based methods like `showDetail(for:)`, so individual screens request navigation without hard-coding destinations — decoupling them and removing duplicated link logic. Modeling routes as an enum makes the app's possible destinations explicit and exhaustive. Because routing then lives in a plain object, you can unit-test navigation decisions without any UI. This pattern keeps large apps' navigation coherent and is a common expectation on professional teams.

## 💡 What You'll Gain

You will centralize navigation in a testable router, decoupling screens from destinations and keeping complex navigation coherent.

## 📚 Dictionary for Developers

*   **Coordinator/Router:** An object owning and directing navigation flow.
*   **Route:** A value representing a navigable destination.
*   **Decoupling:** Separating a screen from knowledge of where it navigates.
*   **Navigation Logic:** The rules deciding what to show next, testable in isolation.
