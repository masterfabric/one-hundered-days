# Day 1: Swift Fundamentals - Environment & Variables

## 📝 Today's Tasks

1.  **Install the Toolchain:** Install the **latest stable Xcode** from the App Store; it ships the current Swift compiler, the current iOS SDK, and the Simulator.
2.  **Run Swift in a Playground:** Create a Playground (or use `swift` in the terminal) and print `"Hello, Swift!"` to confirm the toolchain works.
3.  **Declare Constants and Variables:** Use `let` for values that never change and `var` for values that do. Prefer `let` by default.
4.  **Explore Core Types:** Get hands-on with `Int`, `Double`, `String`, and `Bool`, and let the compiler infer their types.

## 📖 Task Explanations

Start with the toolchain, because everything else depends on it. Install the latest stable Xcode from the App Store — it bundles the Swift compiler, the current iOS SDK, the Simulator, and the debugger in one download. It is a large install, so start it before you do anything else, and open it once when it finishes so it can install its additional components.

With Xcode ready, prove it works. Create a Playground (File → New → Playground) and print `"Hello, Swift!"`, or run `swift` in the terminal for a REPL if you prefer. A Playground executes code as you type and shows results in the sidebar, which makes it the ideal place to try today's syntax without the ceremony of a full app project.

Now the first real decision Swift asks of you: `let` or `var`. `let` declares an immutable binding whose value is fixed after assignment; `var` declares one you can reassign. Declare a few of each and try mutating a `let` to see the compiler stop you. Reaching for `let` by default isn't a style nicety — it lets the compiler catch accidental mutation and reason about your code more aggressively.

Finally, get hands-on with the core types: `Int`, `Double`, `String`, and `Bool`. Write `let count = 42` and option-click the name in Xcode to see that the compiler inferred `Int` for you. Type inference means you rarely write types out loud, but every value still has a precise static type underneath — a fact that becomes important the moment you mix an `Int` and a `Double` in the same expression.

## 💡 What You'll Gain

By the end of today, you will have a working, up-to-date Swift / Xcode setup and can declare correctly-typed constants and variables. This is the bedrock for everything that follows.

## 📚 Dictionary for Developers

*   **Xcode:** Apple's IDE that bundles the Swift compiler, SDKs, Simulator, and debugging tools.
*   **`let`:** Declares an immutable binding whose value is fixed after assignment.
*   **`var`:** Declares a mutable variable whose value can be reassigned.
*   **Type Inference:** The compiler deducing a value's type from context so you needn't write it explicitly.
*   **Playground:** An Xcode file that runs Swift code immediately and shows results inline.
