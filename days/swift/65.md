# Day 65: Advanced SwiftUI UI - Reusable Component Library

## 📝 Today's Tasks

1.  **Extract a Component Set:** Build a small library of buttons, cards, and badges.
2.  **Document with Previews:** Give each component rich `#Preview` states.
3.  **Apply Consistent Tokens:** Drive components from shared color/spacing tokens.
4.  **Package for Reuse:** Move the library into its own SPM module.

## 📖 Task Explanations

This day consolidates the section by building a real, reusable component library. You extract your recurring UI — primary/secondary buttons, cards, badges, section headers — into named components driven by shared design tokens (colors, spacing, corner radii), so the whole app changes consistently from one place. Rich previews act as living documentation and a visual test suite. Packaging the library into its own SPM module makes it reusable across apps and enforces a clean boundary. A well-built component library is a force multiplier for every screen you build afterward.

## 💡 What You'll Gain

You will assemble a documented, token-driven component library in its own module, accelerating and unifying all future UI work.

## 📚 Dictionary for Developers

*   **Component Library:** A curated set of reusable UI components.
*   **Design Token:** A shared value (color, spacing) that components reference.
*   **Preview as Documentation:** Using `#Preview` to showcase and verify component states.
*   **Reusable Module:** An SPM package exposing the component library.
