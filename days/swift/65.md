# Day 65: Advanced SwiftUI UI - Reusable Component Library

## 📝 Today's Tasks

1.  **Extract a Component Set:** Build a small library of buttons, cards, and badges.
2.  **Document with Previews:** Give each component rich `#Preview` states.
3.  **Apply Consistent Tokens:** Drive components from shared color/spacing tokens.
4.  **Package for Reuse:** Move the library into its own SPM module.

## 📖 Task Explanations

Go through your app and pull out the UI you keep rewriting — primary and secondary buttons, cards, badges, section headers, empty states. Give each a name and a clear set of inputs. The test for whether something belongs in the library is repetition plus stability: if it appears on three screens and its shape has stopped changing, extract it.

Give each component a rich set of previews — every variant, every state, long text, short text. These act as living documentation for anyone using the library (including you in two months) and as a visual test suite: scanning them after a change surfaces a broken component immediately.

Drive everything from shared tokens. Define your colours, spacing values, corner radii, and typography once, and have every component reference them rather than hard-coding numbers. That indirection is what makes a design change a one-file edit, and it's also what stops twelve slightly different greys accumulating over a year.

Finally, move the whole thing into its own SPM module. The compiler then enforces the boundary — only what you mark `public` is usable, and the library cannot accidentally reach back into your app's models. It also builds and previews independently, which is faster, and it makes the library reusable across projects. A component library built this way is a force multiplier for every screen you build afterwards.

## 💡 What You'll Gain

By the end of today, you will assemble a documented, token-driven component library in its own module, accelerating and unifying all future UI work.

## 📚 Dictionary for Developers

*   **Component Library:** A curated set of reusable UI components.
*   **Design Token:** A shared value (color, spacing) that components reference.
*   **Preview as Documentation:** Using `#Preview` to showcase and verify component states.
*   **Reusable Module:** An SPM package exposing the component library.
*   **Component API:** The public inputs a component accepts, and nothing more.
