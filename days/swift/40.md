# Day 40: Lists & Navigation - Project: To-Do MVP

## 📝 Today's Tasks

1.  **Model the Data:** Define an `@Observable` store and an `Identifiable` `Task` model.
2.  **Build the List Screen:** Show tasks in a `List` with add, toggle-complete, and delete.
3.  **Add a Detail/Edit Screen:** Navigate to edit a task via `NavigationStack` and `@Bindable`.
4.  **Persist with @AppStorage or in-memory:** Keep state across the session; wire everything together.

## 📖 Task Explanations

Start with the data. Define a `Todo` struct conforming to `Identifiable` with a `UUID`, a title, and an `isDone` flag, then an `@Observable final class TodoStore` holding `var todos: [Todo]` plus the methods that change it — `add`, `toggle`, `delete`. Keeping mutations on the store rather than scattered through views is what makes the rest of the app easy to reason about.

Build the list screen next. A `List` with `ForEach` over the store's todos, a row showing the title and a checkmark, `.onDelete` wired to the store's delete method, and a tap or button that toggles completion. Add new items with a toolbar `+` that presents a sheet or appends directly — either is fine for an MVP, and choosing quickly matters more than choosing perfectly.

Then add the edit screen. Wrap the list in a `NavigationStack`, push with a value-based `NavigationLink`, and in the destination use `@Bindable` to bind text fields straight to the todo. This is where the pieces from Days 31–39 have to actually cooperate: observation, bindings, and navigation all touching the same source of truth.

Finally, make state survive. `@AppStorage` can hold a JSON-encoded array if you want persistence today, or you can keep everything in memory and accept that a relaunch clears it — SwiftData arrives on Day 56 and will replace whatever you do here. Either way, run the full loop end to end: add, edit, complete, delete, relaunch. Making independently-learned pieces work together as one app is the skill this day exists to build.

## 💡 What You'll Gain

By the end of today, you will ship your first complete SwiftUI app, integrating models, state, lists, and navigation into a working To-Do MVP.

## 📚 Dictionary for Developers

*   **MVP:** A Minimum Viable Product: the smallest complete, working app.
*   **Store:** An observable object holding the app's source-of-truth data.
*   **CRUD:** Create, Read, Update, Delete — the core data operations.
*   **Integration:** Making independently-learned pieces work together as one app.
*   **Source of Truth Store:** A single observable object other views read from and write through.
