# Day 76: UI Testing & Accessibility - XCUITest

## 📝 Today's Tasks

1.  **Record a UI Test:** Create an `XCUITest` that launches and drives the app.
2.  **Query Elements:** Find views by accessibility identifier.
3.  **Assert UI State:** Verify labels, existence, and enabled state.
4.  **Handle Async UI:** Wait for elements with expectations.

## 📖 Task Explanations

Create a UI test target and record a flow: Xcode writes the interaction code as you tap through the running app. Recording is a starting point, not the deliverable — the generated queries are usually brittle, and your job is to rewrite them into something stable.

That means querying by accessibility identifier. Set `.accessibilityIdentifier("loginButton")` on the views a test needs, then find them with `app.buttons["loginButton"]`. Identifiers are invisible to users and stable across copy changes, unlike the visible labels a recording will have captured — a test keyed to button text breaks the day marketing rewrites it, and breaks in every localisation.

Assert on real state: `XCTAssertTrue(app.staticTexts["welcomeMessage"].exists)`, plus checks on `isEnabled` and `label` where it matters. Interact through the same query objects with `.tap()` and `.typeText()`, and use `app.launchArguments` to put the app into a known state — a test that depends on whatever data happens to be on the device is not a test.

Finally, handle timing properly. UI tests run against a real, asynchronous app, so use `waitForExistence(timeout:)` or an `XCTestExpectation` rather than sleeping. And keep the number of these small: they're slow and comparatively fragile, so reserve them for the few flows where a break is unacceptable — sign-in, checkout, the core creation path — and let unit tests cover everything else.

## 💡 What You'll Gain

By the end of today, you will write end-to-end UI tests with XCUITest for your app's critical flows, driving the real interface and asserting its state.

## 📚 Dictionary for Developers

*   **XCUITest:** Apple's framework for automated UI testing.
*   **Accessibility Identifier:** A stable string used to locate a view in tests.
*   **Element Query:** Finding UI elements to interact with or assert on.
*   **Expectation:** A wait for an asynchronous UI condition to become true.
*   **Launch Argument:** A flag passed at launch to put the app into a known test state.
