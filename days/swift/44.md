# Day 44: User Input & Forms - Validation

## 📝 Today's Tasks

1.  **Validate as You Type:** Derive validity from state and disable submit when invalid.
2.  **Show Inline Errors:** Display per-field messages for invalid input.
3.  **Validate on Submit:** Run full validation before accepting a form.
4.  **Model Validation Cleanly:** Keep validation logic in the model/view model, not the view.

## 📖 Task Explanations

Validation guards your data's integrity and guides the user. The cleanest approach derives validity from state — a computed property that says whether the form is submittable — so the submit button's enabled state and any inline error messages update reactively as the user types. Keeping the actual rules in the model or view model (not scattered through the view) makes them testable and reusable. Combining live, per-field feedback with a final check on submit gives users immediate guidance while ensuring bad data never gets through.

## 💡 What You'll Gain

You will validate user input reactively and keep validation logic testable, preventing bad data while guiding users to correct it.

## 📚 Dictionary for Developers

*   **Validation:** Checking that input meets required rules before acceptance.
*   **Derived Validity:** Computing a form's submittable state from its inputs.
*   **Inline Error:** A message shown next to the field that failed validation.
*   **Separation of Concerns:** Keeping validation logic out of the view layer.
