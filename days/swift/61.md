# Day 61: Advanced SwiftUI UI - Custom ViewModifiers

## 📝 Today's Tasks

1.  **Write a `ViewModifier`:** Encapsulate reusable styling in a `ViewModifier`.
2.  **Expose a Convenience Method:** Add a `View` extension for ergonomic use.
3.  **Parameterize Styling:** Accept parameters to vary the modifier's effect.
4.  **Build a Style System:** Assemble a small set of reusable styles.

## 📖 Task Explanations

Write a struct conforming to `ViewModifier` with a `body(content:)` method that applies your chain — padding, background, corner radius, shadow — to whatever it's given. The `content` parameter is the view being modified, so the modifier stays generic: it doesn't know or care what it wraps.

Then add the call site you actually want. `extension View { func cardStyle() -> some View { modifier(CardStyle()) } }` turns `.modifier(CardStyle())` into `.cardStyle()`, which reads like a built-in modifier. This two-piece pattern — struct plus extension — is the convention, and it's worth following even for small modifiers so every custom style is invoked the same way.

Parameterize it next. Give the modifier stored properties (a tint, an emphasis level, a corner radius) and pass them through the extension method with sensible defaults. One definition then covers the variations instead of spawning `cardStyle`, `compactCardStyle`, and `highlightedCardStyle` as three near-identical copies.

Finally, build a small set of them and use nothing else. A handful of named styles — card, badge, section header, primary button — applied consistently is what makes an app look designed rather than assembled. The real payoff comes later: when the design changes, you edit one modifier instead of hunting through forty views, which is the difference between a design system and a find-and-replace.

## 💡 What You'll Gain

By the end of today, you will package reusable styling into custom `ViewModifier`s, building a consistent, maintainable design system for your app.

## 📚 Dictionary for Developers

*   **`ViewModifier`:** A reusable, named package of view configuration.
*   **View Extension:** An extension adding an ergonomic method for a modifier.
*   **Design System:** A consistent, reusable set of styles and components.
*   **Parameterization:** Configuring a modifier's behavior via inputs.
*   **Semantic Styling:** Naming a style by its role rather than by its visual properties.
