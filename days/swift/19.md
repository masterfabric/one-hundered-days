# Day 19: Swift Concurrency - Sendable & Strict Concurrency

## 📝 Today's Tasks

1.  **Enable Strict Concurrency:** Turn on complete concurrency checking in build settings (Swift 6 language mode; requires Swift 6.0+).
2.  **Conform to `Sendable`:** Make a value type `Sendable` so it can cross isolation boundaries safely.
3.  **Use `@MainActor`:** Isolate UI-bound code to the main actor.
4.  **Fix Data-Race Warnings:** Resolve compiler diagnostics by fixing isolation, not suppressing them.

## 📖 Task Explanations

The Swift 6 language mode's headline feature is compile-time data-race safety. The `Sendable` protocol marks types that are safe to pass across concurrency boundaries; the compiler checks conformance and refuses to let unsafe values escape their isolation. `@MainActor` pins code to the main thread, which is exactly where UI updates must happen. When strict concurrency is enabled, the compiler flags every potential data race as an error — and the correct response is to fix the underlying isolation (make types `Sendable`, isolate state to actors) rather than reach for `@preconcurrency` escape hatches. This is what makes concurrent Swift genuinely safe.

## 💡 What You'll Gain

You will satisfy the Swift 6 language mode's strict concurrency checker by designing correct isolation, eliminating data races before your app ever runs.

## 📚 Dictionary for Developers

*   **`Sendable`:** A protocol marking types safe to share across concurrency domains.
*   **Strict Concurrency:** Compile-time checking that flags potential data races as errors (Swift 6 language mode).
*   **`@MainActor`:** An annotation isolating code to the main thread for UI safety.
*   **Data Race:** Unsynchronized concurrent access to shared mutable state.
