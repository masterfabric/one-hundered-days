# Day 19: Swift Concurrency - Sendable & Strict Concurrency

## 📝 Today's Tasks

1.  **Enable Strict Concurrency:** Turn on complete concurrency checking in build settings (Swift 6 language mode; requires Swift 6.0+).
2.  **Conform to `Sendable`:** Make a value type `Sendable` so it can cross isolation boundaries safely.
3.  **Use `@MainActor`:** Isolate UI-bound code to the main actor.
4.  **Fix Data-Race Warnings:** Resolve compiler diagnostics by fixing isolation, not suppressing them.

## 📖 Task Explanations

Turn strict concurrency checking on first, so the compiler starts telling you the truth. In the build settings, set the Swift language mode to 6 (or enable complete concurrency checking on an older mode), and expect a wave of warnings on any existing code. Treat that wave as a map of where your isolation is actually unclear, not as noise to be silenced.

Then work through it with `Sendable`. The protocol marks types that are safe to hand across isolation boundaries; a struct of `Sendable` properties gets the conformance inferred, while a class needs immutable state (or `final` with `let` properties) to qualify honestly. Adding `Sendable` to your model types is usually the single change that clears the most warnings.

`@MainActor` handles the other half. UI state must be read and written on the main thread, and annotating a view model with `@MainActor` isolates all of its members there — the compiler then enforces that every off-main caller hops with `await`. SwiftUI's `View` protocol is already main-actor-isolated, so this mostly means being explicit about the types your views own.

Finally, resist the escape hatches. `@unchecked Sendable` and `@preconcurrency` silence the compiler without making anything safe, so use them only at a boundary with code you cannot change, and leave a comment saying why. Every warning you fix properly — by making a type `Sendable`, moving state into an actor, or isolating it to the main actor — is a data race that can no longer happen at runtime.

## 💡 What You'll Gain

By the end of today, you will satisfy the Swift 6 language mode's strict concurrency checker by designing correct isolation, eliminating data races before your app ever runs.

## 📚 Dictionary for Developers

*   **`Sendable`:** A protocol marking types safe to share across concurrency domains.
*   **Strict Concurrency:** Compile-time checking that flags potential data races as errors (Swift 6 language mode).
*   **`@MainActor`:** An annotation isolating code to the main thread for UI safety.
*   **Data Race:** Unsynchronized concurrent access to shared mutable state.
*   **`@unchecked Sendable`:** An escape hatch asserting thread safety the compiler cannot verify.
*   **Isolation Domain:** The region of code whose mutable state is protected by one actor.
