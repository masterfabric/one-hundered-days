# Day 83: Performance & Concurrency in Practice - Main Actor & Off-Main Work

## 📝 Today's Tasks

1.  **Keep UI on the Main Actor:** Ensure UI-facing state is `@MainActor`-isolated.
2.  **Move Heavy Work Off-Main:** Run parsing/compute in a background task or actor.
3.  **Avoid Blocking the Main Thread:** Never do synchronous heavy work in `body` or on main.
4.  **Hop Actors Deliberately:** Understand the cost of crossing isolation boundaries.

## 📖 Task Explanations

A responsive app keeps the main thread free for UI. `@MainActor` guarantees UI state updates on the main thread, but the flip side is that heavy work — decoding large payloads, image processing, sorting big collections — must run off-main in a background task or a dedicated actor, then hand results back to the main actor. Doing expensive synchronous work on the main thread (or inside a view's `body`) is the classic cause of dropped frames and beach-balls. Structuring work so the main actor only touches UI, and compute happens elsewhere, is core to smooth performance.

## 💡 What You'll Gain

You will keep the UI responsive by isolating UI work to the main actor and moving heavy computation off-main deliberately.

## 📚 Dictionary for Developers

*   **Main Actor:** The isolation domain for main-thread UI work.
*   **Off-Main Work:** Computation performed away from the main thread.
*   **Main-Thread Blocking:** Stalling the UI by doing heavy work on main.
*   **Actor Hop:** Crossing from one isolation domain to another.
