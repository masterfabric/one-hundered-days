# Day 48: Networking (I) - Requests, Headers & POST

## 📝 Today's Tasks

1.  **Build a `URLRequest`:** Set the HTTP method, headers, and body.
2.  **Send JSON:** Encode a `Codable` body with `JSONEncoder` for a POST.
3.  **Add Authorization:** Attach a bearer token header.
4.  **Handle Status Codes:** Branch on 2xx/4xx/5xx and decode error payloads.

## 📖 Task Explanations

Move from `URL` to `URLRequest` and you gain control over everything. Set `httpMethod`, add headers with `setValue(_:forHTTPHeaderField:)`, and pass the request to `URLSession.shared.data(for:)`. Note the two header methods: `setValue` replaces, `addValue` appends — the difference matters for headers that can appear more than once.

For a POST, encode the body from a `Codable` value with `JSONEncoder` and assign it to `httpBody`, then set `Content-Type: application/json`. Forgetting that header is the single most common reason a correct-looking request comes back 400 or 415, because the server has no idea how to parse what you sent.

Authorization is another header: `Bearer <token>` on `Authorization`. Never hard-code a token into the source, and never keep one in `UserDefaults` — the Keychain is where it belongs, which is exactly what Day 60 covers. Build the header in one place inside your client so every authenticated request picks it up automatically.

Finally, branch on the status code deliberately: 2xx is success, 4xx means your request was wrong, 5xx means the server failed. For 4xx, decode the API's error payload rather than showing a generic message — most backends return a structured reason, and surfacing it turns an opaque failure into something the user can act on. Handle 401 specially too, since that's the signal to refresh credentials or send the user back to sign-in.

## 💡 What You'll Gain

By the end of today, you will construct full HTTP requests — methods, headers, auth, and JSON bodies — and handle status codes and error payloads explicitly.

## 📚 Dictionary for Developers

*   **`URLRequest`:** A configurable request specifying method, headers, and body.
*   **`JSONEncoder`:** The object that encodes a value into JSON data.
*   **Bearer Token:** An auth credential sent in the `Authorization` header.
*   **Status Code:** The HTTP result code indicating success or failure category.
*   **Content-Type:** The header telling the server how to interpret the request body.
