# Day 18: Swift Concurrency - Actors

## 📝 Today's Tasks

1.  **Define an `actor`:** Create an actor that guards mutable state (e.g. a cache).
2.  **Await Actor Methods:** Call actor methods with `await` from outside its isolation.
3.  **Understand Reentrancy:** Reason about how an actor can interleave awaits.
4.  **Use `nonisolated`:** Mark stateless members `nonisolated` for synchronous access.

## 📖 Task Explanations

An `actor` is a reference type that protects its mutable state from data races by allowing only one task inside at a time. Any access from outside the actor is asynchronous (`await`), which is how the compiler guarantees serialized access without manual locks. Actors are reentrant: while awaiting, an actor may service other calls, so you must not assume state is unchanged across a suspension point. Members that touch no isolated state can be marked `nonisolated` for direct synchronous use. Actors are the safe home for shared mutable state in concurrent Swift.

## 💡 What You'll Gain

You will protect shared mutable state from data races using actors, replacing error-prone locks with compiler-enforced isolation.

## 📚 Dictionary for Developers

*   **Actor:** A reference type that serializes access to its mutable state.
*   **Isolation:** The boundary that requires `await` to access an actor's state.
*   **Reentrancy:** An actor servicing other work while awaiting inside a method.
*   **`nonisolated`:** A marker letting a stateless member be accessed synchronously.
