# Day 18: Swift Concurrency - Actors

## 📝 Today's Tasks

1.  **Define an `actor`:** Create an actor that guards mutable state (e.g. a cache).
2.  **Await Actor Methods:** Call actor methods with `await` from outside its isolation.
3.  **Trigger Reentrancy:** Put an `await` inside an actor method, call it twice concurrently, and log the interleaving.
4.  **Use `nonisolated`:** Mark stateless members `nonisolated` for synchronous access.

## 📖 Task Explanations

Define an actor that owns some mutable state — an image cache is the canonical example. An actor is a reference type like a class, but the compiler guarantees that only one task executes inside it at a time, so its properties cannot be touched concurrently. You get serialized access with no lock to acquire and no lock to forget.

Calling into it from outside requires `await`, even for a method that does no asynchronous work at all. That `await` is the actor hop: your task may have to wait its turn to enter the actor's isolation domain. Try dropping the `await` to see the compiler refuse, which is the whole safety mechanism made visible.

Now the subtlety that catches everyone: actors are reentrant. When an actor method suspends at an `await` inside itself, the actor is free to service other calls in the meantime, so any state you read before the suspension may have changed after it. Reproduce this by putting an `await` in the middle of a method, calling it twice concurrently, and logging the interleaving — then re-check your invariants after every `await` rather than assuming continuity.

Finally, mark members that touch no isolated state as `nonisolated` so they can be called synchronously without the hop. A computed property returning a constant, or a `Hashable` conformance, are typical cases. Between actors for shared mutable state, `nonisolated` for the parts that need no protection, and value types everywhere else, you have the full toolkit for data-race-free Swift.

## 💡 What You'll Gain

By the end of today, you will protect shared mutable state from data races using actors, replacing error-prone locks with compiler-enforced isolation.

## 📚 Dictionary for Developers

*   **Actor:** A reference type that serializes access to its mutable state.
*   **Isolation:** The boundary that requires `await` to access an actor's state.
*   **Reentrancy:** An actor servicing other work while awaiting inside a method.
*   **`nonisolated`:** A marker letting a stateless member be accessed synchronously.
*   **Global Actor:** An actor isolating code process-wide, such as `@MainActor`.
*   **Actor Hop:** Switching execution from one isolation domain to another at an `await`.
