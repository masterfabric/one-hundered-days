# Day 20: Swift Concurrency - Review & Practice: Async Streams

## 📝 Today's Tasks

1.  **Review the Section:** Rebuild Days 16–19 from memory — an `async` fetch, an `async let` pair, an actor, and a `Sendable` model.
2.  **Consume an `AsyncSequence`:** Iterate values over time with `for await value in stream`.
3.  **Build an `AsyncStream`:** Produce values into an `AsyncStream` from a callback source, and use `AsyncThrowingStream` where it can fail.
4.  **Practice Project — Bridge a Legacy API:** Wrap a completion-handler function with `withCheckedContinuation` and feed its results into a stream your app consumes.

## 📖 Task Explanations

Start by consolidating the section. Without looking at your notes, write an `async` function that fetches and decodes something, run two of them concurrently with `async let`, put the shared mutable state behind an actor, and mark the model `Sendable`. Anything you have to look up is exactly what to re-read — this is the point of a review day.

Then extend the toolkit. Where `async`/`await` delivers a single result, `AsyncSequence` delivers many values over time, and it's the concurrency-native replacement for Combine publishers and callback streams. Consume one with `for await value in stream`, and note that the loop suspends between values rather than blocking, so cancelling the surrounding task ends it cleanly.

To produce a sequence, use `AsyncStream`, feeding it from a timer, a notification, or a delegate callback via its continuation. When the source can fail, `AsyncThrowingStream` lets you finish the stream with an error that surfaces at the consumer's `for try await`. Build both, and remember to call `finish()` — a stream nobody terminates keeps its consumer waiting forever.

Finish with the practice project, which is where migration skills come from. Pick a completion-handler API and wrap it with `withCheckedContinuation` so it becomes awaitable; the checked variant traps at runtime if you resume twice or never resume, which catches the two classic bugs immediately. Chaining that bridged call into an `AsyncStream` gives you an end-to-end example of pulling legacy code into structured concurrency, which is how you will adopt it in a real codebase.

## 💡 What You'll Gain

By the end of today, you will have consolidated the whole concurrency section, handled streams of asynchronous values, and bridged legacy callback APIs into `async`/`await`.

## 📚 Dictionary for Developers

*   **`AsyncSequence`:** A protocol for values produced asynchronously over time.
*   **`AsyncStream`:** A concrete async sequence you feed values into imperatively.
*   **Continuation:** A bridge that turns a callback-based API into an awaitable one.
*   **`for await`:** The loop that consumes an async sequence.
*   **`AsyncThrowingStream`:** An async stream that can terminate with an error.
*   **Checked Continuation:** A continuation that traps if resumed twice or never resumed.
