# Day 20: Swift Concurrency - AsyncSequence & Continuations

## 📝 Today's Tasks

1.  **Consume an `AsyncSequence`:** Iterate values over time with `for await value in stream`.
2.  **Build an `AsyncStream`:** Produce values into an `AsyncStream` from a callback source.
3.  **Bridge Legacy APIs:** Wrap a completion-handler API with `withCheckedContinuation`.
4.  **Handle Errors in Streams:** Use `AsyncThrowingStream` for sequences that can fail.

## 📖 Task Explanations

Where `async`/`await` delivers a single result, `AsyncSequence` delivers many values over time — the concurrency-native replacement for Combine publishers and callback streams. You consume one with `for await`, and you produce one with `AsyncStream`, feeding it from timers, notifications, or delegate callbacks. To adopt the async world incrementally, continuations (`withCheckedContinuation`) bridge old completion-handler APIs into `await`-able functions, with runtime checks that you resume exactly once. These tools let you migrate any codebase to structured, modern concurrency.

## 💡 What You'll Gain

You will handle streams of asynchronous values and bridge legacy callback APIs into `async`/`await`, completing your concurrency toolkit.

## 📚 Dictionary for Developers

*   **`AsyncSequence`:** A protocol for values produced asynchronously over time.
*   **`AsyncStream`:** A concrete async sequence you feed values into imperatively.
*   **Continuation:** A bridge that turns a callback-based API into an awaitable one.
*   **`for await`:** The loop that consumes an async sequence.
