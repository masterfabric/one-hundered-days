# Day 66: Animations - Implicit & Explicit Animation

## 📝 Today's Tasks

1.  **Animate Implicitly:** Attach `.animation(_:value:)` to animate a state change.
2.  **Animate Explicitly:** Wrap a mutation in `withAnimation { }`.
3.  **Choose Timing Curves:** Compare `.easeInOut`, `.spring`, and custom curves.
4.  **Animate Multiple Properties:** Coordinate several animated changes.

## 📖 Task Explanations

SwiftUI animates changes, not frames: you tell it a value changed and how, and it interpolates automatically. Implicit animation (`.animation(_:value:)`) ties an animation to a specific state value, while explicit animation (`withAnimation { }`) animates whatever changes inside the block — often the clearer choice for user-triggered actions. Choosing the right timing curve, especially natural-feeling springs, makes motion feel intentional. Because animation is declarative and state-driven, adding polish is usually a one-line change, which is one of SwiftUI's great pleasures.

## 💡 What You'll Gain

You will animate state changes with implicit and explicit animation and natural timing curves, adding polish with minimal code.

## 📚 Dictionary for Developers

*   **Implicit Animation:** Animation tied to a value via `.animation(_:value:)`.
*   **Explicit Animation:** Animation of changes inside a `withAnimation` block.
*   **Timing Curve:** The rate function shaping an animation over time.
*   **Spring:** A physics-based, natural-feeling animation curve.
