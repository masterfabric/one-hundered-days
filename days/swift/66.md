# Day 66: Animations - Implicit & Explicit Animation

## 📝 Today's Tasks

1.  **Animate Implicitly:** Attach `.animation(_:value:)` to animate a state change.
2.  **Animate Explicitly:** Wrap a mutation in `withAnimation { }`.
3.  **Choose Timing Curves:** Compare `.easeInOut`, `.spring`, and custom curves.
4.  **Animate Multiple Properties:** Coordinate several animated changes.

## 📖 Task Explanations

The first thing to internalise is that SwiftUI animates *state changes*, not frames. You never write a frame loop; you change a value, and SwiftUI interpolates every affected property between the old and new rendering. Everything today follows from that.

Implicit animation attaches to a value: `.animation(.easeInOut, value: isExpanded)` animates whatever this view renders differently when `isExpanded` changes. Always use the `value:` form — the deprecated version without it animated every change to the view, including ones you never intended.

Explicit animation wraps the mutation instead: `withAnimation { isExpanded.toggle() }`. Everything that changes as a result animates, wherever it lives in the hierarchy. For user-triggered actions this is usually the clearer choice, since the animation is declared at the cause rather than scattered across every affected view.

Then choose the curve deliberately. `.easeInOut` is a safe default, but `.spring` — and its `.smooth`, `.snappy`, `.bouncy` presets — feels more natural for anything the user directly manipulates, because it carries momentum rather than following a fixed schedule. Coordinating several properties at once is the payoff: change three values inside one `withAnimation` and they move together as a single gesture, which is what makes motion feel intentional rather than decorative.

## 💡 What You'll Gain

By the end of today, you will animate state changes with implicit and explicit animation and natural timing curves, adding polish with minimal code.

## 📚 Dictionary for Developers

*   **Implicit Animation:** Animation tied to a value via `.animation(_:value:)`.
*   **Explicit Animation:** Animation of changes inside a `withAnimation` block.
*   **Timing Curve:** The rate function shaping an animation over time.
*   **Spring:** A physics-based, natural-feeling animation curve.
*   **Interpolation:** Computing the intermediate values between an animation's start and end.
