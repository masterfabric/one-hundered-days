# Day 17: Swift Concurrency - Structured Concurrency

## 📝 Today's Tasks

1.  **Run Work in Parallel:** Use `async let` to start two requests concurrently and await both.
2.  **Use a Task Group:** Spawn a dynamic number of child tasks with `withTaskGroup`.
3.  **Handle Cancellation:** Check `Task.isCancelled` and respond to cooperative cancellation.
4.  **Reason About Task Trees:** Understand how child tasks inherit priority and are awaited by their parent.

## 📖 Task Explanations

Start with `async let`. Writing `async let a = fetchUser()` and `async let b = fetchPosts()` starts both immediately, and `let (user, posts) = try await (a, b)` waits for both together — two one-second calls now take one second instead of two. The work begins at the binding, not at the `await`, which is the detail that makes the parallelism happen.

When the number of operations isn't known at compile time, use a task group. `withTaskGroup(of:)` lets you `addTask` in a loop and then consume results with `for await`, and `withThrowingTaskGroup` propagates the first error. Results arrive as they complete rather than in submission order, so collect them into a dictionary keyed by input if order matters.

Cancellation is cooperative, which means nothing is forcibly stopped — your code has to check. Poll `Task.isCancelled` inside long loops and return early, or call `try Task.checkCancellation()` to throw at that point. System APIs like `URLSession` already check for you, so a cancelled network task throws on its own; the checks you add matter most in your own CPU-bound work.

Finally, look at the shape of the whole thing. Child tasks inherit their parent's priority and task-local values, a parent scope cannot exit until every child has finished, and cancelling a parent cancels the entire subtree. That guarantee is what "structured" means, and it's why this model doesn't leak the orphaned background work that older concurrency approaches so easily produced.

## 💡 What You'll Gain

By the end of today, you will run work in parallel safely, with lifetimes and cancellation managed by the structure of your task tree rather than by hand.

## 📚 Dictionary for Developers

*   **Structured Concurrency:** A model tying concurrent tasks to a lexical scope and parent-child hierarchy.
*   **`async let`:** A binding that starts async work concurrently and awaits it later.
*   **Task Group:** A scope that spawns and collects a dynamic set of child tasks.
*   **Cancellation:** Cooperative signaling that a task should stop work early.
*   **Child Task:** A task created inside a parent scope, awaited and cancelled together with it.
*   **`Task.checkCancellation()`:** A call that throws when the surrounding task has been cancelled.
