# Day 17: Swift Concurrency - Structured Concurrency

## 📝 Today's Tasks

1.  **Run Work in Parallel:** Use `async let` to start two requests concurrently and await both.
2.  **Use a Task Group:** Spawn a dynamic number of child tasks with `withTaskGroup`.
3.  **Handle Cancellation:** Check `Task.isCancelled` and respond to cooperative cancellation.
4.  **Reason About Task Trees:** Understand how child tasks inherit priority and are awaited by their parent.

## 📖 Task Explanations

Structured concurrency ties the lifetime of concurrent work to a clear scope. `async let` runs several operations in parallel and awaits their results together, while task groups spawn a variable number of child tasks and collect their outputs. The key guarantee is structure: a parent task cannot finish until its children do, cancellation propagates down the tree, and errors surface predictably. This eliminates the leaked, orphaned background work that plagued older concurrency models and makes parallelism safe and composable.

## 💡 What You'll Gain

You will run work in parallel safely, with lifetimes and cancellation managed by the structure of your task tree rather than by hand.

## 📚 Dictionary for Developers

*   **Structured Concurrency:** A model tying concurrent tasks to a lexical scope and parent-child hierarchy.
*   **`async let`:** A binding that starts async work concurrently and awaits it later.
*   **Task Group:** A scope that spawns and collects a dynamic set of child tasks.
*   **Cancellation:** Cooperative signaling that a task should stop work early.
