# Day 29: Layout & Composition - Alignment Guides

## 📝 Today's Tasks

1.  **Align Across Stacks:** Use alignment to line up children on a shared edge.
2.  **Use Custom Alignment Guides:** Define an alignment guide to align disparate views.
3.  **Overlay & Background Alignment:** Position overlays/backgrounds with `alignment:`.
4.  **Debug Layout:** Use `.border` and the view-hierarchy debugger to inspect sizing.

## 📖 Task Explanations

Start with the alignment a stack already gives you. A `VStack(alignment: .leading)` lines its children up on their leading edges, and nesting stacks with matching alignments is enough for most screens. Build a row of a label and a multi-line body and notice how the alignment choice, not any offset, is what makes the text block hang together.

Custom alignment guides solve the harder case: lining up views that live in *different* containers. Extend `VerticalAlignment` with your own guide, apply `.alignmentGuide(...)` to the participating views to say where that guide sits within each one, then use it as the container's alignment. This is how an icon in one column lines up with a specific line of text in another, without a single hard-coded offset.

Overlays and backgrounds take their own alignment. `.overlay(alignment: .topTrailing) { Badge() }` pins a badge to a corner, and `.background(alignment:)` works the same way behind the view. Because the layered content doesn't affect the parent's size, this is the right tool for badges, gradients, and decorations that shouldn't push anything around.

Finally, learn to debug layout rather than guess at it. A temporary `.border(.red)` on a few views shows the frames they actually received — usually revealing that a view is much larger or smaller than you assumed. Xcode's view-hierarchy debugger (Debug → View Debugging → Capture View Hierarchy) shows the same thing in 3D for a running app. Between the two, you diagnose layout instead of nudging offsets until it looks right.

## 💡 What You'll Gain

By the end of today, you will achieve precise alignment across your UI using guides and layered positioning, and debug layout issues methodically.

## 📚 Dictionary for Developers

*   **Alignment Guide:** A customizable reference SwiftUI uses to align views.
*   **Overlay/Background:** Layers drawn in front of or behind a view with their own alignment.
*   **Baseline:** The line text sits on, usable as an alignment reference.
*   **Layout Debugging:** Techniques like `.border` to visualize view frames.
*   **Coordinate Space:** The frame of reference a view's position and size are measured in.
