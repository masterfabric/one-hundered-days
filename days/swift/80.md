# Day 80: UI Testing & Accessibility - Test Strategy & the Testing Pyramid

## 📝 Today's Tasks

1.  **Balance the Pyramid:** Favor many unit tests, some integration, few UI tests.
2.  **Choose What to Test:** Prioritize critical logic and flows over trivia.
3.  **Set Up CI Test Runs:** Plan to run tests automatically (previewing the CI/CD section).
4.  **Write Testable Code:** Refactor for injection and pure functions to enable testing.

## 📖 Task Explanations

A good test strategy is about proportion, not maximalism. The testing pyramid prescribes many fast unit tests at the base, fewer integration tests in the middle, and a handful of slow UI tests at the top for critical end-to-end flows — a shape that maximizes confidence per second of test time. Deciding what deserves a test (business logic, money paths, tricky edge cases) and what doesn't (trivial getters) keeps the suite valuable. Writing testable code in the first place — dependency injection, pure functions, thin views — is what makes this whole strategy achievable, which is why architecture and testing reinforce each other.

## 💡 What You'll Gain

You will design a balanced test strategy along the testing pyramid, investing test effort where it yields the most confidence.

## 📚 Dictionary for Developers

*   **Testing Pyramid:** A model favoring many unit, some integration, few UI tests.
*   **Integration Test:** A test exercising several components together.
*   **Testability:** How easily code can be tested, driven by its design.
*   **Test Strategy:** A deliberate plan for what and how to test.
