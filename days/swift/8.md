# Day 8: Types & Protocols - Enums with Associated Values

## 📝 Today's Tasks

1.  **Model State with an `enum`:** Define `enum LoadState { case idle, loading, loaded(Data), failed(Error) }`.
2.  **Attach Associated Values:** Carry payloads inside cases and extract them in a `switch`.
3.  **Add Raw Values:** Back an enum with `String` or `Int` raw values and use `init?(rawValue:)`.
4.  **Add Methods & Computed Properties:** Give an enum behavior with a computed property.

## 📖 Task Explanations

Model a state machine with an enum: `enum LoadState { case idle, loading, loaded(Data), failed(Error) }`. Four lines describe an entire async lifecycle, and — crucially — no other state is representable. A struct with `isLoading`, `data`, and `error` properties allows nonsense combinations like loading *and* failed at once; the enum does not.

Extract those payloads with a `switch`. Each case can carry associated values, and `case .loaded(let data):` binds the payload into a local constant for that branch only. This is where enums earn their keep: the data is available exactly where it is valid and nowhere else, so there is no optional to unwrap and no invalid state to guard against.

Raw values serve a different purpose. Backing an enum with `String` or `Int` gives every case a constant underlying value, useful for persistence, API contracts, and `CaseIterable` menus. `init?(rawValue:)` is failable for the obvious reason — unknown input has no case — so decide deliberately whether an unrecognised value should be an error or fall back to a default.

Finally, give the enum behaviour. Enums can hold methods, computed properties, and protocol conformances just like structs, so a `var isTerminal: Bool` or a `var displayName: String` belongs on the type itself rather than in a helper function elsewhere. Keeping the logic next to the cases means adding a new case makes the compiler point you at every place that needs updating.

## 💡 What You'll Gain

By the end of today, you will model finite state precisely with enums and associated values, making invalid combinations impossible to represent and forcing exhaustive handling.

## 📚 Dictionary for Developers

*   **Enum:** A type defining a fixed set of related cases.
*   **Associated Value:** Data attached to a specific enum case.
*   **Raw Value:** A constant underlying value (e.g. `String`) backing each case.
*   **Exhaustiveness:** The compiler guarantee that a `switch` handles every case.
*   **`CaseIterable`:** A protocol giving an enum an `allCases` collection of its cases.
