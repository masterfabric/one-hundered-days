## 📖 Task Explanations

Begin with a from-memory rebuild of the section: annotate a class with `@Model`, attach a `ModelContainer`, read it back with `@Query`, link a second model with a relationship and a delete rule, and declare a `VersionedSchema`. Reconstructing the whole stack in one sitting is what turns five days of separate APIs into one mental model.

Then add sync. SwiftData can replicate a user's data across their devices through CloudKit with relatively little setup — a private database, no server code — but your models must follow its constraints. Properties need defaults or must be optional, and unique constraints aren't supported, so plan for reconciliation rather than assuming a single writer. Adjust an existing model until it satisfies these rules and watch a change on one device appear on another.

Secrets are a separate problem. Auth tokens, passwords, and refresh tokens must never sit in `UserDefaults` or a plain SwiftData store, both of which are readable from a device backup. The Keychain is the system's encrypted credential store; save one token to it, read it back, and set an accessibility level such as `.afterFirstUnlock` so a background refresh can still reach it.

The audit ties it together. Walk through your app's data and give each item a home: Keychain for secrets, SwiftData for models you query, `@AppStorage` for trivial preferences, and files for blobs like images and video. Writing down *why* for each one is the part that sticks, and it's the same judgement you'll be asked for in any code review of a persistence layer.

## 📚 Dictionary for Developers

*   **CloudKit:** Apple's cloud backend that can sync SwiftData across devices.
*   **Sync Constraints:** Model requirements CloudKit sync imposes.
*   **Keychain:** The system's encrypted store for sensitive credentials.
*   **Storage Selection:** Choosing the appropriate store for each kind of data.
*   **Private Database:** The per-user CloudKit database SwiftData sync writes into.
*   **Keychain Accessibility:** The setting controlling when a stored secret can be read.
