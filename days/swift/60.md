# Day 60: Persistence with SwiftData - CloudKit Sync & Keychain

## 📝 Today's Tasks

1.  **Enable CloudKit Sync:** Configure SwiftData to sync across a user's devices via CloudKit.
2.  **Design for Sync:** Follow constraints (optional properties, no unique-by-default) sync requires.
3.  **Store Secrets in Keychain:** Save tokens/passwords in the Keychain, not UserDefaults.
4.  **Choose the Right Store:** Match each kind of data to the appropriate storage.

## 📖 Task Explanations

Persistence isn't one-size-fits-all. SwiftData can sync a user's data across their devices through CloudKit with relatively little setup, provided your models follow sync constraints (like optional properties and avoiding certain uniqueness rules). Sensitive data — auth tokens, passwords — must never sit in UserDefaults or a plain store; it belongs in the Keychain, the system's encrypted credential store. Part of professional persistence is matching each kind of data to the right home: Keychain for secrets, SwiftData for models, `@AppStorage` for trivial preferences, files for blobs.

## 💡 What You'll Gain

You will sync data across devices with CloudKit and store secrets securely in the Keychain, choosing the right store for each data type.

## 📚 Dictionary for Developers

*   **CloudKit:** Apple's cloud backend that can sync SwiftData across devices.
*   **Sync Constraints:** Model requirements CloudKit sync imposes.
*   **Keychain:** The system's encrypted store for sensitive credentials.
*   **Storage Selection:** Choosing the appropriate store for each kind of data.
