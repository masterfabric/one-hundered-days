# Day 84: Performance & Concurrency in Practice - Debugging Data Races

## 📝 Today's Tasks

1.  **Enable the Thread Sanitizer:** Run with TSan to catch races at runtime.
2.  **Read Compiler Isolation Errors:** Interpret Swift 6 strict-concurrency diagnostics.
3.  **Fix by Isolating State:** Resolve races by moving state into actors or the main actor.
4.  **Audit `Sendable` Conformance:** Ensure shared types are genuinely safe to send.

## 📖 Task Explanations

Even with Swift 6's compile-time checks, understanding data races deeply pays off. The Thread Sanitizer catches races that slip through at runtime, and reading strict-concurrency diagnostics carefully tells you exactly which state is unsafely shared. The fix is almost always structural: isolate mutable state into an actor or the main actor, or make a shared type genuinely `Sendable` — not to silence the compiler with escape hatches. Auditing your `Sendable` conformances ensures the guarantees are real. This is the skill that keeps concurrent apps correct under load, where races are notoriously hard to reproduce.

## 💡 What You'll Gain

You will diagnose and fix data races through proper isolation and honest `Sendable` conformance, keeping concurrent code correct under load.

## 📚 Dictionary for Developers

*   **Data Race:** Unsynchronized concurrent access to shared mutable state.
*   **Thread Sanitizer:** A runtime tool detecting data races.
*   **Isolation Fix:** Resolving a race by confining state to an actor/main actor.
*   **`Sendable` Audit:** Verifying shared types are truly safe to transfer.
