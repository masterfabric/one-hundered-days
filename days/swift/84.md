# Day 84: Performance & Concurrency in Practice - Debugging Data Races

## 📝 Today's Tasks

1.  **Enable the Thread Sanitizer:** Run with TSan to catch races at runtime.
2.  **Read Compiler Isolation Errors:** Interpret the Swift 6 language mode's strict-concurrency diagnostics.
3.  **Fix by Isolating State:** Resolve races by moving state into actors or the main actor.
4.  **Audit `Sendable` Conformance:** Ensure shared types are genuinely safe to send.

## 📖 Task Explanations

Turn on the Thread Sanitizer in your scheme's diagnostics and run the app. TSan instruments memory access and reports races as they happen, with both stack traces — the write and the conflicting access. It slows the app considerably, so use it in a dedicated run rather than leaving it on, and exercise the concurrent paths deliberately while it's active.

Then learn to read the compiler's isolation diagnostics rather than pattern-matching a fix. "Sending value of non-Sendable type" and "actor-isolated property cannot be referenced from a nonisolated context" each name precisely which value crosses which boundary. Slow down and identify the state and the two domains involved; the fix follows from that, and guessing usually just moves the error.

Fix structurally. Confine the mutable state to an actor, isolate it to `@MainActor`, or make the type a `Sendable` value type so there's nothing to share. Each of these removes the race; adding `@unchecked Sendable` merely removes the warning while leaving the bug for a user to find under load.

Finally, audit your existing `Sendable` conformances, especially any `@unchecked` ones you added under deadline. For each, ask what actually guarantees thread safety — immutability, an internal lock, confinement to one actor — and write that reason in a comment. If you can't state it, the conformance is a lie, and races are notoriously hard to reproduce once they reach production.

## 💡 What You'll Gain

By the end of today, you will diagnose and fix data races through proper isolation and honest `Sendable` conformance, keeping concurrent code correct under load.

## 📚 Dictionary for Developers

*   **Data Race:** Unsynchronized concurrent access to shared mutable state.
*   **Thread Sanitizer:** A runtime tool detecting data races.
*   **Isolation Fix:** Resolving a race by confining state to an actor/main actor.
*   **`Sendable` Audit:** Verifying shared types are truly safe to transfer.
*   **Race Report:** A sanitizer output naming the two conflicting accesses and their stacks.
