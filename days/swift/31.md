# Day 31: State & Data Flow - @State & @Binding

## 📝 Today's Tasks

1.  **Hold Local State:** Drive UI from a `@State` property and watch it re-render on change.
2.  **Mutate from Controls:** Bind a `Toggle`/`Slider` to state with the `$` projection.
3.  **Pass a Binding Down:** Share write access to state with a child via `@Binding`.
4.  **Keep State Minimal:** Store the smallest source of truth and derive the rest.

## 📖 Task Explanations

Declare `@State private var count = 0` and render it. The wrapper tells SwiftUI to store that value outside the struct — remember views are recreated constantly — and to re-run `body` whenever it changes. Keep it `private` and keep it small: `@State` is for value types the view itself owns, not for shared models.

Then hand write access to a control. `Toggle("On", isOn: $isOn)` uses the `$` prefix, which exposes the property's *projected value* — a `Binding` that reads and writes the underlying storage. That's the whole mechanism behind every SwiftUI control: they don't own their data, they borrow a two-way reference to yours.

Passing that binding down is the same idea one level further. A child declares `@Binding var count: Int` and the parent passes `$count`; the child can now write to state it doesn't own, and both views update. Use this for a child that genuinely edits the parent's data, and plain `let` properties for a child that only displays it — an unnecessary binding is a small design smell.

Finally, keep the source of truth minimal. If you store `items` and also `itemCount`, the two can disagree; store `items` and make `itemCount` a computed property, and they can't. The same goes for `isValid`, filtered lists, and formatted strings — derive them. Every piece of redundant state is a bug waiting for the moment you forget to update it.

## 💡 What You'll Gain

By the end of today, you will drive reactive UI from local state and share write access with bindings, internalizing SwiftUI's single-source-of-truth principle.

## 📚 Dictionary for Developers

*   **`@State`:** A property wrapper for a view's own mutable value-type state.
*   **`@Binding`:** A two-way reference to state owned elsewhere.
*   **Projected Value (`$`):** The `Binding` exposed by a state property.
*   **Source of Truth:** The single authoritative place a piece of state lives.
*   **Derived State:** A value computed from the source of truth rather than stored separately.
