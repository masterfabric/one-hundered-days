# Day 31: State & Data Flow - @State & @Binding

## 📝 Today's Tasks

1.  **Hold Local State:** Drive UI from a `@State` property and watch it re-render on change.
2.  **Mutate from Controls:** Bind a `Toggle`/`Slider` to state with the `$` projection.
3.  **Pass a Binding Down:** Share write access to state with a child via `@Binding`.
4.  **Keep State Minimal:** Store the smallest source of truth and derive the rest.

## 📖 Task Explanations

State is what makes SwiftUI dynamic. `@State` declares a small piece of value-type state owned by a view; when it changes, SwiftUI recomputes the affected part of the `body`. The `$` prefix creates a `Binding`, a two-way connection you hand to controls (or to child views via `@Binding`) so they can read and write your state. The guiding principle is a single source of truth: store the minimal essential state and compute everything else from it, which keeps your UI consistent and bug-free.

## 💡 What You'll Gain

You will drive reactive UI from local state and share write access with bindings, internalizing SwiftUI's single-source-of-truth principle.

## 📚 Dictionary for Developers

*   **`@State`:** A property wrapper for a view's own mutable value-type state.
*   **`@Binding`:** A two-way reference to state owned elsewhere.
*   **Projected Value (`$`):** The `Binding` exposed by a state property.
*   **Source of Truth:** The single authoritative place a piece of state lives.
