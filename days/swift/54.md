# Day 54: Networking (II) & Architecture - Dependency Injection

## 📝 Today's Tasks

1.  **Inject via Initializers:** Pass dependencies into view models through their init.
2.  **Provide via Environment:** Inject shared services through the SwiftUI environment.
3.  **Define Protocol Abstractions:** Depend on protocols so implementations are swappable.
4.  **Compose the Object Graph:** Wire real dependencies together at the app's entry point.

## 📖 Task Explanations

Dependency injection (DI) means a component receives its collaborators rather than creating them. Constructor injection (passing a repository into a view model's init) makes dependencies explicit and swappable; the SwiftUI environment injects shared services deep into the tree without manual threading. Depending on protocols everywhere lets you assemble the real object graph at the app's entry point while substituting fakes in tests. Good DI is the quiet foundation that makes an app modular, testable, and easy to reconfigure as requirements change.

## 💡 What You'll Gain

You will wire your app's dependencies explicitly and swappably, the practice that makes an architecture modular and testable.

## 📚 Dictionary for Developers

*   **Dependency Injection:** Supplying a component's collaborators from outside.
*   **Constructor Injection:** Passing dependencies through an initializer.
*   **Object Graph:** The wired-together set of an app's objects and dependencies.
*   **Composition Root:** The single place dependencies are assembled (the app entry point).
