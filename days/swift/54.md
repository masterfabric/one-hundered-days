# Day 54: Networking (II) & Architecture - Dependency Injection

## 📝 Today's Tasks

1.  **Inject via Initializers:** Pass dependencies into view models through their init.
2.  **Provide via Environment:** Inject shared services through the SwiftUI environment.
3.  **Define Protocol Abstractions:** Depend on protocols so implementations are swappable.
4.  **Compose the Object Graph:** Wire real dependencies together at the app's entry point.

## 📖 Task Explanations

Start with constructor injection, the default. `init(repository: TaskRepositoryProtocol)` makes every dependency visible in the type's signature: you can read the initializer and know exactly what this object needs to work. A type that reaches out to a singleton instead hides those needs and can't be tested without the real thing.

The environment covers what constructor injection makes awkward — a service needed by many views at different depths. `.environment(analytics)` at the root and `@Environment(Analytics.self)` where it's used avoids threading a parameter through views that don't care. The tradeoff is that a missing injection fails at runtime rather than compile time, so reserve it for genuinely app-wide services.

Depend on protocols in both cases. The concrete `URLSession`, the real analytics SDK, the actual clock — each hides behind a small protocol declaring only what you use. Keep those protocols narrow: a two-method protocol is trivial to fake, while one mirroring an entire SDK is not, and the size of the fake you'd have to write is a good measure of whether the abstraction is right.

Finally, assemble everything in one place — the composition root, usually your `App` struct. Construct the real client, the repositories, and the services there and pass them down. Every other type receives what it needs and constructs nothing, so switching to a mock backend for a demo build, or a fake for a test, is a change in one file rather than a hunt through the codebase.

## 💡 What You'll Gain

By the end of today, you will wire your app's dependencies explicitly and swappably, the practice that makes an architecture modular and testable.

## 📚 Dictionary for Developers

*   **Dependency Injection:** Supplying a component's collaborators from outside.
*   **Constructor Injection:** Passing dependencies through an initializer.
*   **Object Graph:** The wired-together set of an app's objects and dependencies.
*   **Composition Root:** The single place dependencies are assembled (the app entry point).
*   **Singleton:** A globally shared instance, which hides dependencies and resists testing.
