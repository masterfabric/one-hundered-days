# Day 34: State & Data Flow - Environment & Dependency Injection

## 📝 Today's Tasks

1.  **Read Built-in Environment:** Access values like `\.colorScheme` and `\.dismiss`.
2.  **Inject an Observable:** Provide a model with `.environment(...)` and read it via `@Environment`.
3.  **Define a Custom Environment Value:** Create your own environment key/value.
4.  **Reason About Scope:** Understand how environment values flow down the view tree.

## 📖 Task Explanations

Start with the built-in values. `@Environment(\.colorScheme)` tells you whether the system is in light or dark mode; `@Environment(\.dismiss)` gives you an action to close the current sheet or pop the current screen. Neither was passed to your view by its parent — they arrived implicitly through the environment, which is the point.

Then inject your own. Call `.environment(store)` on a parent view and read it in any descendant with `@Environment(Store.self)`. For `@Observable` types this is the modern spelling, and the descendant can be arbitrarily deep — no threading a parameter through five intermediate views that don't care about it. Note the failure mode: forget the injection and you get a crash at runtime, not a compile error, so inject at the root and test the previews that use it.

Custom environment values let you extend the mechanism to anything. Declare an entry with a default value and add a computed property on `EnvironmentValues`, and now `\.myTheme` behaves exactly like a system value, including being overridable per subtree with a modifier.

Finally, reason about scope, because that's where the real power is. Environment values flow *down* from where they're set, so setting one on a subtree affects only that subtree — a detail screen can override the theme, or a preview can inject a fake service in place of the real one. That last case is the practical payoff: components declare what they need, the environment supplies it, and tests and previews supply something else.

## 💡 What You'll Gain

By the end of today, you will inject dependencies through the environment, decoupling views from how their data and services are constructed.

## 📚 Dictionary for Developers

*   **Environment:** SwiftUI's mechanism for passing values implicitly down the view tree.
*   **`@Environment`:** A wrapper reading a value from the environment.
*   **Dependency Injection:** Supplying a component's dependencies from outside it.
*   **Environment Key:** The type identifying a custom environment value.
*   **Environment Override:** Setting a different value for one subtree of the view hierarchy.
