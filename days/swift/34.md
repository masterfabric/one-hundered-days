# Day 34: State & Data Flow - Environment & Dependency Injection

## 📝 Today's Tasks

1.  **Read Built-in Environment:** Access values like `\.colorScheme` and `\.dismiss`.
2.  **Inject an Observable:** Provide a model with `.environment(...)` and read it via `@Environment`.
3.  **Define a Custom Environment Value:** Create your own environment key/value.
4.  **Reason About Scope:** Understand how environment values flow down the view tree.

## 📖 Task Explanations

The environment is SwiftUI's built-in dependency-injection system. Values placed into the environment flow implicitly down the view tree, so any descendant can read them without threading parameters through every intermediate view. You use it for framework values (`\.colorScheme`, `\.dismiss`) and, powerfully, to inject your own `@Observable` services and models so deep views can access shared dependencies. Defining custom environment values lets you build clean, decoupled architectures where components declare what they need and the environment supplies it.

## 💡 What You'll Gain

You will inject dependencies through the environment, decoupling views from how their data and services are constructed.

## 📚 Dictionary for Developers

*   **Environment:** SwiftUI's mechanism for passing values implicitly down the view tree.
*   **`@Environment`:** A wrapper reading a value from the environment.
*   **Dependency Injection:** Supplying a component's dependencies from outside it.
*   **Environment Key:** The type identifying a custom environment value.
