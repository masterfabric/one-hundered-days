# Day 77: UI Testing & Accessibility - VoiceOver & Semantics

## 📝 Today's Tasks

1.  **Add Accessibility Labels:** Give views clear `.accessibilityLabel` text.
2.  **Set Traits & Values:** Use `.accessibilityAddTraits` and `.accessibilityValue`.
3.  **Group Elements:** Combine related views with `.accessibilityElement(children:)`.
4.  **Test with VoiceOver:** Navigate your app using VoiceOver.

## 📖 Task Explanations

Add `.accessibilityLabel` wherever the visible content isn't self-describing. An icon-only button is the classic case: VoiceOver announces nothing useful for `Image(systemName: "trash")` on its own, so the label is what turns it into "Delete". Write labels as what the control *does*, not what it looks like — "Delete", not "Trash icon".

Then supply traits and values. `.accessibilityAddTraits(.isButton)` tells VoiceOver an element is tappable, `.isHeader` lets users jump between sections, and `.accessibilityValue` reports a control's current setting — a slider's number, a toggle's state. Traits carry the semantics that a purely visual design communicates through position and styling.

Group related elements so navigation isn't tedious. `.accessibilityElement(children: .combine)` merges a row's icon, title, and subtitle into one element read as a single phrase, instead of three separate stops. On a list of twenty rows, that's the difference between a usable screen and an exhausting one.

Finally, turn VoiceOver on and use your app with the screen off — add it to the Accessibility Shortcut so triple-clicking the side button toggles it. Ten minutes of this reveals gaps no visual review catches: unlabelled buttons, elements in an illogical order, controls that announce nothing. SwiftUI's defaults are good, but custom views are exactly where they run out.

## 💡 What You'll Gain

By the end of today, you will make your app usable with VoiceOver by providing correct semantic labels, traits, and values, and by testing it hands-on.

## 📚 Dictionary for Developers

*   **VoiceOver:** Apple's screen reader for non-visual navigation.
*   **Accessibility Label:** The text VoiceOver reads for a view.
*   **Accessibility Trait:** Semantic role info (button, header, selected).
*   **Element Grouping:** Combining views into one accessible element.
*   **Accessibility Value:** The current setting a control reports, such as a slider's number.
