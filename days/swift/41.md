# Day 41: User Input & Forms - TextField & TextEditor

## 📝 Today's Tasks

1.  **Capture Text:** Bind a `TextField` to state and set a prompt/placeholder.
2.  **Configure the Keyboard:** Set `.keyboardType`, `.textContentType`, and `.submitLabel`.
3.  **Multi-line Input:** Use `TextEditor` or an `axis: .vertical` text field.
4.  **Handle Submission:** Respond to `.onSubmit` and return-key actions.

## 📖 Task Explanations

A `TextField` takes a `Binding`, so declare `@State private var name = ""` and pass `$name`. Every keystroke writes straight back into your state and re-renders the views that read it — there is no delegate and no manual sync. Give the field a prompt so the user knows what it wants, and try `.textFieldStyle(.roundedBorder)` to see the built-in styles.

Configuring the field is what makes entry fast and correct. `.keyboardType(.emailAddress)` brings up the right keys, `.submitLabel(.next)` changes the return key's label, and `.textContentType(.emailAddress)` is the one people forget — it's the hint that enables system autofill for emails, passwords, addresses, and one-time codes. Add `.autocorrectionDisabled()` and `.textInputAutocapitalization(.never)` for fields like usernames, where autocorrect does more harm than good.

For longer input you have two options. `TextField("Notes", text: $notes, axis: .vertical)` keeps the familiar field but grows as the user types, and you can bound it with `.lineLimit(3...8)`. `TextEditor` gives you a plain scrolling multi-line area instead, which suits a full note or comment screen — it has no prompt of its own, so add your own placeholder overlay if you need one.

Submission is the last piece. `.onSubmit { ... }` runs when the user taps the return key, which is where you validate, move focus to the next field, or trigger the search. Getting these details right — the correct keyboard, working autofill, a sensible return key — is the difference between a form that feels effortless and one users abandon.

## 💡 What You'll Gain

By the end of today, you will capture and configure text input properly, enabling autofill, the right keyboards, and smooth submission handling.

## 📚 Dictionary for Developers

*   **`TextField`:** A single-line text input control bound to state.
*   **`textContentType`:** A hint enabling autofill (email, password, one-time code).
*   **`TextEditor`:** A multi-line text input view.
*   **`.onSubmit`:** A modifier responding to the return/submit action.
*   **`Binding`:** A two-way reference letting a control read and write your state.
*   **`.submitLabel`:** A modifier setting the return key's title, such as `.next` or `.done`.
